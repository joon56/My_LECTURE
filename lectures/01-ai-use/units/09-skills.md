# 단원 9 · 반복 절차를 Skill로 만들고 적용 범위 확인하기

## 강의 목표와 준비

프로젝트 지침과 Skill의 차이, 이름·설명·본문·보조 자료의 역할을 이해한다. 강사는 CSV 검토 예시로 적용 상황과 실패 처리를 설명한다. 문서 형식·발견·로딩·실제 동작의 차이를 배운다.

> **PDF 연결 | 새로 추가**
> 물리적 38–41쪽의 지속적 맥락·하네스를 구체화하는 추가 단원이다. 원본은 Agent Skills 규격, `SKILL.md` 메타데이터, 두 제품의 설치 위치·호출법을 설명하지 않는다. 장면 1–2에는 반복 절차를 묶는 법, 장면 3–4에는 공식 규격과 적용 검사를 새로 넣었다. 이 구현이 원문의 유일한 하네스 구현이라고 설명하지 않는다.

## 개념 설명 · 언제나 지킬 규칙과 필요할 때 꺼낼 절차

프로젝트 지침의 “원본을 보존한다”는 여러 작업에 적용된다. “CSV의 열·단위·누락값·시간 순서를 차례로 검토한다”는 특정 작업의 절차다. Skill은 이런 절차와 필요한 자료를 재사용할 수 있게 묶는다. 이름과 설명은 호스트·모델이 어떤 작업에 관련되는지 판단하는 데 쓰이고, 본문은 실제 수행 방법을 담는다.

Skill을 만든다고 새 모델을 훈련하는 것은 아니다. 필요한 지침·참조 자료·선택적 스크립트를 제공한다. 모델이 선택하고 해석하는 단계가 있으므로 정확성을 보장하는 실행 프로그램과 동일하지 않다. 반복 계산은 검증한 코드를 사용하고, Skill은 언제 무엇을 실행·확인할지 안내할 수 있다.

## 장면 1 · Skill로 만들 가치가 있는 작업 고르기

**강사 대본**

“처음 한 번 하는 일은 짧은 요청으로 충분할 수 있습니다. 같은 검토를 여러 파일에서 반복하고, 매번 같은 항목을 놓친다면 절차를 묶을 이유가 생깁니다. ‘연구를 잘해주는 Skill’보다 ‘측정 CSV의 입력 오류를 보고하는 Skill’이 검증하기 쉽습니다. 범위가 작아야 언제 성공했는지도 명확합니다.”

**판서·비교**

- 이번 그래프 제목 수정 → 이번 요청.
- 원본 보존 → 프로젝트 지침.
- 여러 측정 CSV를 같은 순서로 검토 → Skill 후보.
- CSV 평균 계산 → 검증한 계산 코드.
- 외부 저장소의 CSV 조회 → 연결 도구가 필요한지 별도 판단.

**학생 질문**: “반복 작업이면 전부 Skill로 만들까요?”

**예상 답**: 이미 간단한 명령이나 함수로 해결되는지 먼저 본다. 절차가 아직 자주 바뀌면 작업 기록·체크리스트로 다듬는다. 재사용 가치와 유지 비용을 함께 판단한다.

## 장면 2 · 이름·설명·본문으로 최소 초안 작성

**강사 대본**

“설명에는 무엇을 하는지만 적지 말고 언제 쓰는지도 적습니다. 본문에는 실제 필요한 단계와 결과 형식을 적습니다. ‘알아서 분석한다’는 문장 대신, 단위가 없을 때 추측할지 질문할지 정합니다. 오류 입력에서 정상 결과를 내지 않도록 실패 처리도 포함합니다.”

**예시 폴더**

```text
csv-review/
└── SKILL.md
```

아래는 문서 안의 예시다. 활성 Skill 폴더에 설치하거나 현재 도구에 등록한 것이 아니다.

````markdown
---
name: csv-review
description: 측정 CSV의 열, 단위, 누락값과 시간 순서를 검토할 때 사용한다. 자동 보정이나 장비 제어는 수행하지 않는다.
---

# 측정 CSV 검토

## 입력 확인

입력 파일, 필요한 열, 단위, 오류 정책을 확인한다.
결과에 영향을 주는 기준이 없으면 먼저 확인한다.

## 절차

1. 파일과 열 이름을 읽는다.
2. 누락값, 비숫자, 중복 시간, 역순 시간을 검사한다.
3. 오류는 데이터 행 번호, 열, 이유로 보고한다.
4. 오류 입력은 정상 요약을 생성하지 않는다. 원본은 보존한다.
5. 정상 입력은 명세의 변환과 예상값을 계산 도구로 대조한다.
6. 실제 수행과 미실행 검사를 구분한다.

## 보고 항목

입력 / 검사 기준 / 실제 결과 / 오류 위치 / 미확인 / 다음 행동
````

YAML frontmatter는 맨 앞의 `---` 사이 메타데이터다. 이 예의 `name`과 폴더명은 `csv-review`로 맞춘다. 이름에 관한 길이·문자 제한과 지원 필드는 [Agent Skills 규격](https://agentskills.io/specification)을 확인한다. Markdown 제목을 잘 썼어도 메타데이터가 깨지면 발견·로딩에 문제가 생길 수 있다.

**학생 질문**: “좋은 결과 예시도 넣어야 하나요?”

**예상 답**: 형식이나 판정이 헷갈릴 때 짧은 입력·출력 예를 넣는다. 긴 자료는 보조 파일로 분리할 수 있다. 절차를 설명하는 데 필요하지 않은 자료까지 모두 붙이지 않는다.

## 장면 3 · 두 도구의 위치와 호출을 구분하기

**강사 대본**

“공통 규격이 있다고 모든 호스트의 경로와 메뉴가 같아지는 것은 아닙니다. 오늘은 사용할 도구 하나의 프로젝트 경로부터 확인합니다. 파일을 복사한 다음 이름이 보이는지, 실제로 본문이 읽히는지, 예상 행동을 하는지 순서대로 확인합니다.”

**공식 문서 확인, 로컬 실행 미검증 — 2026-10-03**

| 도구 | 프로젝트 위치 예 | 명시 호출 예 |
|---|---|---|
| Codex CLI·IDE | `.agents/skills/csv-review/SKILL.md` | `$csv-review` |
| Claude Code | `.claude/skills/csv-review/SKILL.md` | `/csv-review` |

실제 지원 위치·자동 발견·조직 정책은 [Codex skills](https://learn.chatgpt.com/docs/build-skills), [Claude Code skills](https://code.claude.com/docs/en/skills)에서 확인한다. 두 도구의 전용 필드를 서로 그대로 복사하지 않는다. 동일 이름의 다른 Skill이 있다면 어느 파일이 선택됐는지 확인한다.

**호출 요청 예**

```text
csv-review 절차로 data/normal.csv를 검토해줘.
기준은 requirements.md를 사용해줘.
실제로 읽은 Skill 파일과 수행한 검사, 미확인 검사를 보고해줘.
```

명시 호출 표기와 탐색 규칙은 호스트마다 다르다. 발견 실패의 원인에는 이름·위치·로딩 조건이 있다. 전체 설정을 출력해 인증 정보까지 수집하는 방식은 사용하지 않는다.

**학생 질문**: “이름이 목록에 뜨면 성공인가요?”

**예상 답**: 발견 단계는 확인됐다. 실제 본문 로드와 검사 수행은 별도다. 선택된 파일이 맞는지도 확인해야 한다.

## 장면 4 · 정상·오류·비대상 요청으로 검사

**강사 대본**

“정상 입력에서 평균을 구하는 것만 보면 일반 모델이 답한 것인지 절차가 작동한 것인지 구별하기 어렵습니다. 빠뜨리기 쉬운 누락값, 없는 단위, 관련 없는 글쓰기 요청을 함께 봅니다. Skill의 품질에는 해야 할 일을 하는 것뿐 아니라 적용할 필요가 없는 상황을 구별하는 것도 포함됩니다.”

**완성된 검사 명세**

| 입력·요청 | 기대 결과 | 확인할 증거 |
|---|---|---|
| 1000·2000·3000mV 정상 CSV | 평균 2V, 기준 대조 | 계산 실행과 비교 |
| 데이터 2행 전압 누락 | 행·열 보고, 자동 보정 없음 | 오류 보고와 원본 |
| 단위 없는 열 | 명세 확인·필요하면 질문 | 추측한 변환 여부 |
| 자기소개 문장 교정 | CSV 절차를 억지 적용하지 않음 | 실제 선택·답변 |

예상 출력의 최소 형식은 다음과 같다. 실제 값은 실행 후 기록한다.

```text
사용한 Skill: <확인한 파일>
입력: <파일>
검사 기준: <명세 위치>
수행 결과: <관찰한 값·오류>
미실행: <이유>
```

**학생 질문**: “한 번 안 불렸으면 Skill이 나쁜 건가요?”

**예상 답**: 이름·설명 문제, 로딩 실패, 관련성 판단, 명시 호출 지원 여부를 나눠 조사한다. 성공·실패 하나만으로 원인을 확정하지 않는다.

## 오개념과 강의 요점

- Skill은 모델 능력을 영구 학습한다 → 현재 작업의 지침·도구 사용을 돕는다.
- Skill은 모두 텍스트뿐이다 → 보조 코드·자료를 포함할 수 있다.
- YAML 통과는 행동 검증이다 → 형식·호스트 로딩·실행을 따로 확인한다.

강의 요점: Skill은 필요할 때 재사용할 절차다. 정상·오류·정보 부족·비대상 요청을 구별한다.
