# 단원 10 · MCP로 외부 도구를 연결하고 실제 사용 확인하기

## 강의 목표와 준비

MCP의 호스트·클라이언트·서버 역할과 등록·연결·호출·판정의 차이를 이해한다. 강사는 공개 문서 조회의 구조와 실패 사례를 설명한다. 설정 명령 실행은 챕터말 선택 확장에서 다룬다.

> [!NOTE]
> **PDF 연결 | 새로 추가**
> 물리적 38–41쪽의 에이전트 도구 호출과 하네스를 구체화한다. 원본은 MCP 규격·서버 연결 명령을 설명하지 않는다. 장면 1의 구조, 장면 2의 읽기 전용 연결, 장면 3의 호출 증거, 장면 4의 실패 진단은 공식 문서에 근거해 새로 추가했다. MCP가 모든 에이전트의 필수 조건이라는 뜻은 아니다.

## 개념 설명 · 모델이 사용할 기능을 연결하는 약속

MCP는 Model Context Protocol의 약자다. AI 애플리케이션과 외부 도구·자료를 제공하는 프로그램 사이의 통신 규약이다. 호스트는 전체 작업을 관리하는 Codex·Claude Code 같은 앱이다. 클라이언트는 호스트 안에서 서버와의 연결을 맡는다. 서버는 사용할 기능이나 자료를 제공한다. 서버는 내 컴퓨터에서 실행될 수도, 원격 서비스일 수도 있다.

Skill은 “어떤 절차로 일할지”를 안내하고, MCP 서버는 “호스트가 어떤 외부 기능을 호출할 수 있는지”를 제공할 수 있다. 둘을 함께 쓸 수도 있지만 어느 하나가 다른 하나를 자동 포함하지 않는다. CSV가 이미 로컬에 있고 필요한 계산 도구가 있으면 그 계산에 MCP를 추가할 필요는 없다.

## 장면 1 · 도구 결과가 모델로 돌아오는 길

**강사 대본**

“모델이 최신 설정 문서를 확인해야 한다고 합시다. 연결된 검색 도구가 있다면 검색을 요청하고 결과를 받습니다. 그 결과를 읽어 최종 답을 씁니다. 연결 규약은 이 왕복을 돕습니다. 하지만 검색된 문서가 적절한지, 답이 그 문서를 정확히 요약했는지는 여전히 확인해야 합니다.”

**판서**

```text
사용자 질문
    ↓
호스트 안의 모델 → MCP 클라이언트 → 문서 MCP 서버
    ↑                                 ↓
최종 답변 해석   ← 조회한 문서·링크  ← 검색·본문 조회
```

“서버를 연결했다”, “검색 도구가 제공됐다”, “실제로 호출했다”, “원문에 맞게 답했다”를 각각 칸에 적는다. 하나가 성공했다고 나머지 칸에 체크하지 않는다.

**학생 질문**: “MCP가 검색 엔진인가요?”

**예상 답**: 통신 규약이다. 검색을 제공하는 서버도 있고 다른 작업을 제공하는 서버도 있다. 제공 기능과 접근 범위는 서버마다 다르다.

## 장면 2 · 읽기 전용 공식 문서 서버로 시작하기

**강사 대본**

“오늘은 문서 검색·본문 조회만 제공하는 OpenAI Docs MCP를 예로 씁니다. 실제 연구 자료를 올리거나 쓰기 도구를 시험할 필요가 없습니다. 명령 실행 전에 설치 버전과 저장 범위를 확인합니다. 예시 명령을 읽는 것과 내 설정을 바꾸는 것을 구별합시다.”

**공식 문서 확인, 로컬 실행 미검증 — 2026-10-03**

이 서버는 OpenAI 개발자 문서를 읽기 전용으로 제공하며 사용자 대신 OpenAI API를 호출하는 서버가 아니다. [Docs MCP 공식 안내](https://developers.openai.com/learn/docs-mcp).

**설정 범위 개념도**

```text
학생 프로젝트/
└── notes/mcp-check.md      학생이 작성하는 검사 기록

호스트 설정 위치는 별도:
Codex 기본 사용자 설정 → ~/.codex/config.toml 등
Claude 프로젝트 공유 설정 → 프로젝트 .mcp.json 등
```

위는 위치 설명이다. 서로 다른 제품의 설정 파일을 통째로 복사하거나 전역 파일을 덮어쓰라는 절차가 아니다. 기존 서버 이름·범위와 설치 버전 도움말을 먼저 확인한다. 명령에서 `--help`, `list`는 확인용이고 `add`는 등록 변경이다.

강사 설명: `list`는 상태 확인, `add`는 등록 변경이다. Codex의 기본 사용자 설정과 Claude Code의 local·project 범위는 다르다. 정확한 등록·해제 방법은 설치 버전의 공식 문서와 도움말을 기준으로 확인한다. 명령과 수행 기록은 챕터말 선택 확장에 모았다.

**학생 질문**: “명령을 지금 모두 실행해야 하나요?”

**예상 답**: 계정·설치·권한을 확인한 실습 환경에서만 등록한다. 연결 실습을 하지 못하면 공식 웹 문서를 열어 같은 근거 대조를 할 수 있다. 이 경우 MCP 실행 성공으로 기록하지 않는다.

## 장면 3 · 답변보다 호출 기록부터 보기

**강사 대본**

“최종 답이 자세하다고 조회한 것은 아닐 수 있습니다. 오늘 확인할 대상은 도구 호출과 반환 자료입니다. 어떤 검색을 했는지, 어느 문서를 읽었는지, 결론이 문서의 어느 내용을 요약했는지 연결해 보겠습니다.”

**입력 요청**

```text
연결한 OpenAI 공식 문서 도구로 AGENTS.md의 프로젝트 적용 범위를 찾아줘.
관련 본문을 읽고 이번 프로젝트에서 확인할 사항을 정리해줘.
실제로 사용한 링크와 조회하지 못한 부분을 구별해줘.
설정은 변경하지 마.
```

**확인할 증거:** 호스트·버전, 이름·범위, 연결 상태, 실제 도구·질의, 반환 URL, 답변과 원문의 대조 결과다.

기대 산출물은 적용 범위 설명, 그 설명을 지지하는 공식 원문 링크, 자기 환경에서 추가 확인할 항목이다. 정확한 도구 이름·화면은 버전별로 달라질 수 있어 가짜 호출 로그를 미리 적지 않는다. 결과에 문서 링크가 있어도 실제 호출 증거가 없으면 “링크 제시, MCP 사용 여부 미확인”으로 남긴다.

**학생 질문**: “공식 문서를 가져왔으면 답도 정확한가요?”

**예상 답**: 다른 제품·버전 문서를 가져왔거나 조건을 생략할 수 있다. 문서의 적용 범위와 최종 문장을 직접 대조한다.

## 장면 4 · 실패 위치를 나누어 진단하기

**강사 대본**

“연결이 안 되면 같은 등록 명령을 반복하지 않습니다. 저장 여부, 연결 상태, 도구 제공 여부, 실제 호출 실패를 나눕니다. 오류 메시지에서 필요한 부분만 기록하고, 토큰이나 전체 인증 설정을 화면에 올리지 않습니다. 오늘 목표는 연결 원리를 배우는 것이므로 실패 자체도 정확히 분류하면 학습 자료가 됩니다.”

| 관찰 | 다음 확인 |
|---|---|
| 목록에 서버 없음 | 저장 범위·시작 환경·등록 오류 |
| 목록에는 있으나 연결 실패 | 주소·네트워크·호스트 오류 메시지 |
| 연결됐으나 도구 안 보임 | 제공 기능·호스트 지원·세션 상태 |
| 도구는 있으나 호출 안 함 | 실제 요청과 도구 선택 |
| 호출 성공, 결론 틀림 | 반환 본문과 최종 해석 대조 |

**학생 질문**: “서버가 읽기 전용이면 모든 위험이 없어지나요?”

**예상 답**: 쓰기 영향은 줄지만 잘못된 정보 해석이나 부적절한 질의 전송까지 없어지는 것은 아니다. 이 수업은 공개 문서 질문만 사용한다. 외부 자료 속 지시문을 사용자 명령으로 승격하지 않는다.

## 강의 요점과 근거

강의 요점: 등록·연결·호출·원문 대조는 별개다. 성공한 단계까지만 보고한다.

[MCP 공식 구조](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture), [Docs MCP](https://developers.openai.com/learn/docs-mcp), [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [Claude MCP](https://code.claude.com/docs/en/mcp). 제품 문서 확인일 2026-10-03. 이 단원 제작에서는 등록 명령 실행·설정 변경·서버 호출을 수행하지 않았다.
