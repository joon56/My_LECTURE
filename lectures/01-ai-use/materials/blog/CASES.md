## C1 실행은 되지만 단위 변환이 틀린 사례

과제: 전압 1000 mV를 V로 바꾼다. 단위 정의상 1000 mV = 1 V다.

```python
voltage_mv = 1000
print(voltage_mv / 100)
```

이 코드는 10.0을 출력할 수 있지만 원하는 변환값은 1.0이다. 수정할 식은 `/ 1000`이다. 오류 없이 실행되는 것과 요구한 계산이 맞는 것은 구별된다. 이 사례는 강의 제작자가 만든 작은 반례이며 실제 연구실 사건이 아니다. 학생이 직접 실행하지 않았다면 학생 실행 결과로 기록하지 않는다.

검증 범위: 이 숫자와 단위의 관계를 손계산으로 확인할 수 있다. 다른 입력·전체 프로그램·보안·성능을 모두 검증했다는 뜻은 아니다.

## C3 사실 검토용 결함 원고와 의뢰 문장

S04는 아래 의도적인 결함 네 개를 검토한다. 실제 모델 출력이나 통계가 아니다.

**모든 학생에게 같은 의뢰 문장:** “실행되고 AI가 검토했으면 정확하다고 강조해줘.”

```text
AI가 만든 코드는 실행만 되면 믿어도 될까?

프로그램이 오류 없이 종료되면 계산 결과도 정확하다고 보면 된다.
AI가 코드를 한 번 더 검토했다면 사람이 따로 확인할 필요가 없다.
Python의 assert는 -O 옵션에서도 항상 실행되므로 검사 누락 걱정이 없다.
이 방식을 사용하면 코드 정확성이 90% 향상된다.
따라서 실행과 AI 재검토만 마치면 모든 조건의 검증이 끝난다.
```

검토 기준: 실행과 정확성의 혼동, AI 재검토의 과신, assert 조건 오류, 근거 없는 90% 수치를 근거로 판정한다. 마지막 문장은 앞선 오류를 종합한 잘못된 결론이다. 무조건 반대하기보다 맞는 부분과 교정할 부분을 구분한다.

### 고정 원고 시작

# AI가 만든 코드는 실행만 되면 믿어도 될까?

## 실행과 정답은 다르다

코드가 실행됐다는 사실은 그 실행에서 프로그램이 동작했다는 증거다. 원하는 계산이 맞는지는 입력과 기준을 대조해야 한다. GitHub도 Copilot이 만든 코드의 검토와 테스트를 권한다. [S1](https://docs.github.com/en/copilot/responsible-use/chat)

## 작은 값으로 확인하기

1000 mV는 1 V다. 다음 수업용 코드는 100으로 나눠 10.0을 출력한다. 실행 오류가 없더라도 변환식은 틀렸다.

```python
print(1000 / 100)  # 수업용 단위 변환 오류
```

이 경우에는 1000으로 나누어야 한다. 결과를 보고 기준을 바꾸기 전에 단위 정의로 예상값을 정한다.

## 독자가 해볼 확인 세 가지

1. 입력의 의미와 단위를 확인한다.
2. 작은 입력의 예상값을 직접 구하고 실제 값과 비교한다.
3. 빈 입력처럼 실패해야 하는 조건과 검사 실행 여부도 확인한다.

Python 3.12 문서에 따르면 `-O`에서는 assert 검사가 생략된다. 코드에 검사가 적혀 있는지와 실행됐는지를 나누어 보자. [S2](https://docs.python.org/3.12/reference/simple_stmts.html#the-assert-statement)

## 확인한 범위를 남기기

목표와 평가 기준을 먼저 정하고 결과를 비교하는 방식은 OpenAI의 LLM 평가 지침에서도 다룬다. [S3](https://developers.openai.com/api/docs/guides/evaluation-best-practices) 여기의 세 행동은 그 자료와 반례를 수업에 맞게 정리한 제안이다. 몇 개의 검사를 통과했다고 모든 입력·보안·성능을 확인한 것은 아니다.
