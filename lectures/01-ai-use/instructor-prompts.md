# 함께 입력하는 블로그 회사 프롬프트

강사와 학생이 아래 요청문 **한 개**를 함께 입력한다. 목표는 총괄이 실제 하위 에이전트 3개의 결과를 전달하고 글을 완성하는 과정을 보는 것이다.

## 입력 전에

새 blog-company 폴더에 [BRIEF.md](materials/blog/BRIEF.md)를 복사한다. AI 작업 위치를 그 폴더로 연다. 폴더 준비·수업 흐름은 [실습 교안](practice.md), 도구 확인은 [강사 환경 안내](materials/blog/TOOLS.md)를 따른다.

## 공통 프롬프트

```text
현재 폴더의 BRIEF.md를 읽고 블로그 글 한 편을 만드는 작은 회사를 운영해줘.
너는 총괄이다. 실제 하위 에이전트 3개를 만들어 조사·집필·검토를 각각 맡겨줘.
총괄을 포함하면 4개이며, 하위가 추가 에이전트를 만들지 않게 해.
실제 생성 기능이 없으면 지원되지 않는다고 알리고 멈춰줘.
역할 이름만 나열한 답변을 실제 위임했다고 보고하지 마.

공통 주제는 “AI가 만든 코드는 실행만 되면 믿어도 될까?”다.
독자는 AI로 프로그램 과제를 해본 공대 후배다.
제공 자료만 사용하고 입력 파일을 수정하지 마.
자료·역할·반환 형식을 각 담당에게 전달해줘.

1. 조사 담당에게 BRIEF.md의 반례·출처 요약을 전달해.
   글에 쓸 주장·근거·주의할 한계를 짧게 정리해 돌려받아.
2. 조사 결과를 받은 뒤 집필 담당에게 그 결과와 글의 목적을 전달해.
   한국어로 짧은 블로그 초고를 받아. 소제목은 3개 안팎이면 된다.
   단위 변환 반례와 사람이 확인할 행동, 근거 링크를 넣어.
3. 검토 담당에게 BRIEF.md와 실제 초고를 전달해.
   계산·근거 없는 주장·실행 여부 과장을 확인하고,
   수정할 문장과 이유를 돌려받아. 문제가 없으면 없다고 해.
4. 수정이 필요하면 같은 집필 담당에게 검토 의견을 전달해 한 번 보완해.
   총괄이 수정 반영 여부를 확인하고 남은 문제를 알려줘.

하위 담당은 응답으로 결과를 반환하고 파일은 총괄만 저장해.
현재 폴더에 article.md로 최종 원고를,
work.md로 실제 역할·전달한 결과·반영한 수정·남은 확인을 짧게 남겨줘.
하위 작업이 반환될 때마다 누가 무엇을 넘겼는지 한 줄로 알려줘.
조사 결과 없이 집필 완료, 초고 없이 검토 완료라고 쓰지 마.
열지 않은 공식 원문·실행하지 않은 코드·외부 게시를 완료했다고 쓰지 마.
실패하면 어느 담당의 어느 단계에서 멈췄는지 알려줘.
추가 검색·도구 설치·HTML 제작·블로그 업로드는 하지 마.
```

## 강사가 설명할 세 지점

1. **역할과 범위:** 조사·집필·검토를 각각 맡기는 문장이다. 실제 하위 작업 화면을 열어 세 작업이 존재하는지 보여준다.
2. **결과 전달:** 조사 반환→집필 입력, 초고→검토 입력, 검토 의견→집필 보완을 가리킨다. 이 시연에서는 총괄이 중계한다.
3. **마무리:** article.md와 work.md를 직접 연다. 계산 반례 하나와 실제 전달·수정 한 가지를 확인하고 끝낸다.

프롬프트를 먼저 설명한 뒤 학생과 함께 실행한다. 상대 점수나 프롬프트 우열을 측정하지 않는다. 문장이 길거나 에이전트가 많아서 좋은 것이 아니라 맡길 일·자료·받을 결과·순서를 명확히 한 점을 짚는다.

## 예상과 막힘

예상은 실제 하위 작업 세 개의 반환과 최종 두 파일이다. 생성 여부는 도구 화면과 파일로 확인한다. 반환 내용은 모델 실행마다 다를 수 있다. 검토가 문제를 발견하지 않으면 수정 과정을 억지로 만들지 않는다.

학생 환경이 미지원이면 강사 화면으로 관찰한다. 강사도 미지원이면 실제 위임 시연은 미수행이다. 실패한 작업을 자동으로 계속 재시도하거나 추가 역할을 만들지 않는다. 새로운 활동이 필요하면 강사가 범위를 정한 뒤 별도로 진행한다.

이 요청문은 교육용이며, 학생 환경에서의 실제 동작은 수업 전 리허설로 확인한다.
