# 챕터 1 실습 · 함께 만드는 블로그 회사

챕터 1 강의를 마친 뒤 강사와 같은 프롬프트를 입력해 블로그 글 한 편을 만든다. 이번에 볼 것은 **하위 에이전트의 역할 분담과 결과 전달**이다. 짧게 경험한 뒤 강사가 진행할 실제 과제로 넘어간다.

주제: **AI가 만든 코드는 실행만 되면 믿어도 될까?**

## 준비 · 폴더 하나와 입력 파일 하나

사용 가능한 Codex 또는 Claude Code, 텍스트 편집기를 준비한다. 실제 하위 에이전트 지원 여부는 강사가 미리 확인한다. 두 도구를 모두 설치하지 않는다.

1. 강의 저장소 밖에 새 **blog-company** 폴더를 만든다. 같은 이름이 이미 있으면 새 이름을 쓴다.
2. [BRIEF.md](materials/blog/BRIEF.md)를 그 폴더에 복사한다. 공통 제목·계산 반례·출처 요약이 보이는지 연다. 직접 저장하면 UTF-8 텍스트로 저장하고 .md.txt가 되지 않게 한다.
3. AI의 작업 위치를 blog-company로 연다. 강사가 제공한 [공통 프롬프트](instructor-prompts.md)를 함께 읽고 아래 실행 순서로 진행한다.

시작할 때 파일은 BRIEF.md 하나다. 역할별·단계별 폴더를 만들지 않는다. 학생 배포 ZIP을 받았다면 안의 BRIEF.md와 PROMPT.md를 사용한다. README·PROMPT는 사람이 읽는 안내이며 AI에는 요청문과 BRIEF를 제공한다.

## 회사가 일하는 흐름

```text
사람이 요청 → 총괄
              조사 담당 → 근거 요약
              집필 담당 ← 근거 요약 → 초고
              검토 담당 ← 초고·원자료 → 검토 의견
              집필 담당 ← 필요한 수정 의견 → 보완
            → 총괄이 최종 파일 저장 → 사람이 확인
```

하위 에이전트는 조사·집필·검토 **3개**, 총괄까지 합하면 **4개**다. 총괄이 반환 결과를 다음 담당에게 전달한다. 이 흐름에서 에이전트끼리 직접 메시지를 주고받는 기능을 가정하지 않는다. 초고가 있어야 검토할 수 있으므로 모든 작업을 동시에 시작하는 것이 목표는 아니다.

## 같이 실행하기

1. 강사가 공통 프롬프트의 역할·입력·결과·순서를 짚는다. 학생도 같은 요청문을 자기 작업 폴더에서 한 번 입력한다.
2. 강사가 실제 하위 작업 화면을 연다. 조사 결과가 집필자에게, 초고가 검토자에게 전달되는 것을 함께 본다.
3. 검토 의견이 있으면 같은 집필 담당이 보완하는 것을 본다. 문제가 없으면 불필요한 수정을 요구하지 않는다.
4. 완료 후 article.md와 work.md를 직접 열어 아래 항목만 짧게 확인한다.

**예상 결과**

```text
blog-company/
  BRIEF.md     제공 입력
  article.md   검토를 반영한 블로그 글
  work.md      누가 무엇을 넘겼고 무엇을 고쳤는지 짧은 요약
```

## 함께 확인하고 끝내기

- 실제 조사·집필·검토 하위 작업이 보였는가? 총괄이 앞 결과를 다음 담당에게 넘겼는가?
- 최종 글이 열리는가? 1000 mV = 1 V라는 반례를 잘못 설명하지 않았는가?
- work.md에서 역할별 작업과 실제 수정 또는 수정 불필요 판단을 하나 짚을 수 있는가?

별도 채점표·점수·개인별 비교 보고서는 없다. 역할 이름을 출력한 문장과 실제 하위 작업을 구분하고, 생성된 글을 한 번 직접 읽는 수준으로 마무리한다.

## 강사용 풀이 · 무엇을 보여주면 되는가

“조사 담당이 넘긴 근거가 여기서 글이 됐고, 검토 의견이 이 문장을 바꿨습니다.”처럼 실제 화면을 연결한다. 수정이 없었다면 검토자가 확인한 항목과 수정 불필요 판단을 보여준다. 협업이 항상 더 빠르거나 정확하다고 결론내리지 않는다.

코드 예제의 /100은 10을 내지만 단위 정의상 1 V가 맞다. 생성된 글이 그 차이를 보존했는지 사람이 확인한다. 따로 코딩·실험 단계를 추가하지 않는다.

## 막히면

파일을 못 읽으면 작업 위치와 BRIEF.md부터 확인한다. 파일을 못 저장하면 응답을 사람이 저장하고 그 사실을 말한다. 실제 하위 에이전트가 미지원인 학생은 강사 화면을 관찰한다. 강사 환경도 미지원이면 실제 위임은 확인하지 못했다고 표시한다.

한 작업이 실패하거나 사용량이 끝나면 멈춘 위치를 확인한다. 시연을 복잡한 복구 실습으로 늘리지 않는다. 도구 지원 확인은 [강사 안내](materials/blog/TOOLS.md)에 있다.

이 실습의 끝은 블로그 **원고** 완성이다. HTML·플랫폼 게시·Git push·지침 파일 제작은 수행 단계에 포함하지 않는다. 실제 랩실 과제는 강사가 별도로 진행한다.
