## 표시를 읽는 법

수업 순서는 **챕터 1 강의 → [챕터 1 실습](../lectures/01-ai-use/practice.md) → 챕터 2 강의 → [챕터 2 실습](../lectures/02-git-and-records/practice.md)**이다. 아래 단원 연결은 강사가 개념과 사례를 설명하는 위치다. 학생이 직접 파일을 만들고 검증·제출하는 활동과 풀이·채점은 해당 챕터 실습에서 진행한다. 강의 중간에 실습을 완료해야 다음 단원을 이해하는 구조로 사용하지 않는다.

| 표시 | 뜻 | 강사가 할 일 |
|---|---|---|
| 활용 | 원문의 개념·사례를 설명에 연결 | 원문 위치를 보여주고 학생 과제로 풀어서 설명 |
| 교정 후 활용 | 범위·수치·주장에 보완이 필요 | 원문과 교정 근거를 함께 보여주고 보완된 설명 사용 |
| 새로 추가 | 원문에 없는 실습·기술 설명 | 원본 보고서의 주장으로 소개하지 않고 별도 출처 제시 |

“활용”은 그대로 복사했다는 뜻이 아니다. 강사 대본·합성 CSV·채점 기준은 이번 교육 설계다. 특히 **Markdown 문법, Skill·MCP·Plugin의 구체적 사용법, Git 명령은 새로 보강한 내용**이다. 원문의 에이전트·지침 논의와 연결되더라도 원문이 해당 제품 기능을 설명한 것으로 간주하지 않는다.

1. **C1-01 장면 2:** 5~10쪽에서 모델 원리를 짚은 뒤 실제 파일 읽기 기록을 보여준다. 수식 설명과 제품의 행동을 구분한다.
2. **C1-03:** 17쪽 워크플로우를 보여주고 “각 단계가 끝났다는 것을 무엇으로 확인할까?”를 묻는다. 명세와 확인 기록이 답이 된다.
3. **C1-04 → C1-02 연결:** 29쪽의 잘 정리된 출력에서 수치를 하나 고른다. 원 논문 대조 후 “보기 좋은 형식”과 “내용 정확성”을 따로 평가한다.
4. **C1-07:** 39쪽의 반복 흐름에 현재 프로젝트의 지침·도구·검사를 대응시킨다. 자연어 지침만으로 강제되는 범위라고 말하지 않는다.
5. **C1-12:** 42~44쪽의 결론을 학생 작업에 적용한다. “AI가 작성한 것, 내가 정한 것, 직접 검증한 것”을 각각 한 문장으로 설명하게 한다.
