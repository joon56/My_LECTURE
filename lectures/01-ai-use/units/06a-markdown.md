# 보충 단원 · Markdown으로 AI 작업 문서 읽고 고치기

## 강의 목표와 준비

Markdown 원문과 표시 결과의 관계를 이해한다. 제목·목록·링크·코드 블록과 YAML 메타데이터의 역할을 구분한다. 강사는 원문·미리보기·수정 전후 규칙을 보여준다. 문서 표시·호스트 로딩·실제 실행은 별개다.

> [!NOTE]
> **PDF 연결 | 새로 추가**
> 원본에는 Markdown 문법 강의가 없다. 물리적 38–41쪽의 에이전트·지침 파일 설명을 실제로 읽고 고치기 위한 선수 내용이다. 장면 1–2에는 원문/미리보기 읽기, 장면 3에는 게임 모드 비유와 한계, 장면 4에는 지침 수정·검증을 새로 넣었다. Markdown 자체가 실행·자동 적용을 보장한다는 설명으로 확대하지 않는다.

## 먼저 설명할 개념

Markdown은 일반 텍스트에 제목, 목록, 강조, 링크 같은 구조를 표시하는 문서 형식이다. `.md`는 흔히 쓰는 확장자다. `#`는 제목 표시이고, `-`는 목록 표시다. 편집기는 표시를 그대로 보여주거나 이를 읽기 좋은 화면으로 렌더링한다. 렌더링은 문서를 표시하는 일이다. 그 안의 Python 코드나 터미널 명령이 자동 실행된다는 뜻은 아니다.

AI 작업에서는 사람이 수정하기 쉽고, 도구가 텍스트로 읽기 쉽고, 변경 전후를 비교하기 쉬워 자주 쓴다. 하지만 파일을 저장하는 일과 모델이 그 파일을 읽는 일은 별개다. 일반 메모는 요청으로 읽게 할 수 있고, `AGENTS.md`나 `SKILL.md`는 지원하는 호스트의 탐색·로딩 규칙을 따른다. 호스트는 Codex, Claude Code처럼 모델에 문맥과 도구를 제공하는 실행 프로그램이다.

## 장면 1 · 같은 내용을 두 화면으로 읽기

**강사 대본**

“왼쪽은 원문, 오른쪽은 미리보기입니다. 왼쪽 `#`가 오른쪽에서 큰 제목으로 보입니다. 두 개의 문서가 생긴 게 아닙니다. 한 파일을 두 방식으로 보는 겁니다. AI가 준 자료를 화면으로만 읽으면 제목과 규칙의 위치는 알 수 있지만 정확히 무엇을 고쳐야 할지 놓칠 수 있습니다. 오늘은 원문에서 고치고 미리보기에서 뜻이 유지됐는지 확인합니다.”

**판서·시연**

강사는 아래 원문과 표시 결과를 나란히 보여준다. 예시 파일명은 일반 문서 이름이며 자동 지침 파일명이 아니다.

````markdown
# 측정 데이터 검토

## 입력

- 파일: `sample.csv`
- 전압 단위: **mV**
- 원본은 보존한다.

## 계산 예

```python
voltage_v = voltage_mv / 1000
```

[명세](../SPEC.md)
````

**렌더링에서 확인할 모습**

- “측정 데이터 검토”는 첫 제목, “입력”과 “계산 예”는 하위 제목으로 보인다.
- `sample.csv`는 코드 모양, **mV**는 굵은 글씨로 보인다.
- 계산식은 코드 블록 안에 그대로 표시된다. 실행 결과 `1.0` 등이 새로 나오지 않는다.
- “명세”는 상대 링크다. 이 예시를 실제 저장한 위치와 목적지의 관계를 설명한다.

**학생 질문**: “제목이 작으면 `#`를 더 붙이나요?”

**예상 답**: `#` 수는 제목의 계층이다. `#`가 문서 제목, `##`가 큰 절, `###`가 하위 절이다. 화면 크기만 보고 계층을 뒤집지 않는다.

## 장면 2 · 코드·링크·체크박스가 뜻하는 것

**강사 대본**

“실습 명령을 문장 중간에 쓰면 설명과 명령을 구별하기 어렵습니다. 짧은 이름은 백틱 한 쌍, 여러 줄은 백틱 세 개로 감쌉니다. 닫는 백틱을 빠뜨리면 뒤 설명도 코드처럼 보입니다. 문법 문제지만, 읽는 사람은 지침의 범위를 잘못 이해할 수 있습니다. 예쁜 화면보다 구분이 정확한지가 먼저입니다.”

**판서·시연**

```markdown
- [ ] 정상 입력 결과 확인
- [x] 입력 파일 열 이름 확인

[요구사항](requirements.md)
```

체크박스는 GitHub 등에서 지원하는 확장 문법이다. 체크 표시는 작성자가 상태를 표현한 것이므로 테스트 증거가 아니다. `[x]`가 있어도 어떤 입력으로 무엇을 확인했는지 따로 읽는다. 표·체크박스·경고 상자는 제품마다 지원이 다를 수 있다. 기본 제목·목록·링크·코드 블록부터 쓴다.

상대 링크는 현재 문서의 위치를 기준으로 해석한다. 예를 들어 `notes/check.md`에서 프로젝트 루트의 `requirements.md`로 가려면 `../requirements.md`가 된다. 실제 목적지 파일을 열어 확인한다. 인터넷 주소는 웹 링크이고 컴퓨터 전체 경로는 다른 학생에게 그대로 통하지 않을 수 있다.

**학생 질문**: “코드 블록 위에 `powershell`을 쓰면 PowerShell이 실행되나요?”

**예상 답**: 보통 구문 색상 표시를 위한 언어 이름이다. 실행은 별도의 터미널·도구가 담당한다. 실행 기능을 붙인 편집기에서도 사용자가 실행 동작과 권한을 구별해야 한다.

## 장면 3 · 게임 모드 비유로 이해하고 경계 긋기

**강사 대본**

“게임에 원하는 기능 묶음을 더하듯 AI 작업 도구에도 반복 절차나 연결 도구를 더할 수 있습니다. 이 비유는 기본 도구를 내 작업에 맞춘다는 점에서 유용합니다. 그런데 인터넷에서 `.md`를 받았다고 모든 기능이 켜지지는 않습니다. 모드에 설명서, 설정, 실행 파일이 구분되듯 AI 확장도 지침, 코드, 연결 설정을 따로 읽어야 합니다.”

**판서**

```text
Markdown 문서 → 읽을 내용과 절차
호스트 로딩 규칙 → 어떤 파일을 언제 읽는가
스크립트·도구 → 실제 계산·조회·수정
권한·설정 → 어떤 접근과 실행을 허용하는가
Plugin → 위 구성 요소 일부를 배포하는 묶음
```

지침 수정은 모델의 가중치를 다시 학습시키는 일이 아니다. 이번 작업에서 참조할 조건을 바꾸는 일이다. Skill이 Markdown 중심이어도 보조 스크립트를 포함할 수 있다. Plugin은 코드·설정·외부 연결까지 포함할 수 있으므로 “텍스트 파일이라 모두 안전하다”는 결론도 성립하지 않는다. 게임 모드의 파일 구조나 설치 방식을 AI 제품에 그대로 대응시키지 않는다.

**학생 질문**: “좋은 지침 파일 하나면 모델 성능이 올라가나요?”

**예상 답**: 특정 작업에 필요한 맥락과 절차를 전달할 수 있다. 효과는 해당 작업에서 확인해야 한다. 모델 자체의 모든 능력이 향상됐다고 말할 근거는 없다.

## 장면 4 · 받은 문서를 읽고 최소 수정하기

**강사 대본**

“이제 인터넷 지침을 가져왔다고 가정합시다. 먼저 ‘무슨 상황에서 무엇을 하라는 문서인가’를 설명합니다. 다음으로 내 과제와 충돌하는 문장 하나를 찾습니다. 전체를 멋있게 다시 쓰는 것보다 필요한 한 줄을 고치고 그 효과를 확인하는 편이 쉽습니다. 원문은 남기고 실습용 사본에 수정합니다.”

**입력 예**

```markdown
# CSV 검토

- 누락된 측정값은 자동으로 삭제한다.
- 결과를 간단히 보고한다.
```

**수정 결과 예**

```markdown
# CSV 검토

- 누락된 측정값은 행 위치와 열 이름을 보고한다.
- 삭제·보간은 사용자가 처리 정책을 정하기 전에는 수행하지 않는다.
- 입력, 검사 항목, 실제 결과, 실행하지 못한 검사를 구분해 보고한다.
```

**수정 이유**: 누락값 삭제는 측정 결과에 영향을 준다. 현재 과제는 원본 보존과 오류 보고가 목표다. “간단히”만으로는 실행 여부를 확인할 수 없어 보고 항목을 명시했다. 이것은 이번 과제의 정책이며 모든 데이터 분석에 보편적으로 강제하는 규칙은 아니다.

**학생 질문**: “저장했으니 이제 적용된 건가요?”

**예상 답**: 문서 수정은 끝났다. 일반 문서를 읽어 달라고 요청했는지, 지침 파일로 올바르게 로드됐는지, 실제 누락값 사례에서 행동이 맞는지는 별도 확인이다.

## 오개념과 강의 요점

- `.md`라서 AI가 자동으로 읽는다 → 파일명·위치·호스트 규칙 또는 명시적 읽기 요청이 필요하다.
- 미리보기가 정상이라 기능도 정상이다 → 문서 표시와 호스트 로딩·실행 검사는 다르다.
- 체크박스가 있으면 자동 검사다 → 상태 표기일 수 있으므로 근거를 읽는다.

강의 요점: 문서 수정·미리보기·지침 로딩·실제 행동 확인은 서로 다른 단계다.
