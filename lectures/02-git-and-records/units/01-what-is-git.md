# 01 · Git이란 무엇인가

> [!NOTE]
> **PDF 연결 | 새로 추가**
> 원본 PDF에는 Git의 정의·저장소·커밋을 가르치는 직접 대응 단원이 없다. 이 단원은 작업 결과와 변경 근거를 남기기 위해 강사가 추가한 교육 내용이다. Git 기술 설명은 아래 공식 문서를 근거로 한다.

## 목표·준비·산출물

- 목표: 버전 관리, Git, GitHub를 구분하고 저장·add·commit·push의 역할을 설명한다.
- 준비: 파일과 폴더, 편집기의 저장 기능. Git 설치는 다음 단원에서 확인한다.
- 산출물: 네 도구의 역할 설명과 측정 자료의 변경 이력 그림 한 장.
- 수업 범위: 합성 CSV와 문서. 아직 분석 프로그램을 구현했다고 가정하지 않는다.

## 개념 설명

**Git은 파일의 버전을 기록하고, 변경을 비교하고, 여러 작업 흐름을 합치는 분산 버전 관리 시스템이다.** 버전 관리는 이름 뒤에 `최종`을 붙이는 규칙보다 넓다. 어느 상태가 어떤 상태에서 이어졌는지, 무엇을 바꿨는지, 왜 바꿨는지를 확인할 수 있어야 한다.

Git의 기본 기록 단위는 **커밋(commit)** 이다. 커밋은 선택한 프로젝트 상태를 가리키며 메시지·작성 정보·부모 커밋 관계를 담는다. 최초 커밋에는 부모가 없고 일반 커밋에는 보통 부모가 하나다. 파일 전체를 매번 새로운 폴더로 복사한다는 뜻은 아니다. 개념적으로 스냅샷을 기록하며, 실제 저장은 중복을 줄이는 구조를 사용한다. 학생에게 처음부터 내부 저장 형식을 외우게 할 필요는 없다.

**분산**은 일반적인 `clone`을 하면 내 컴퓨터에도 작업에 필요한 저장소 이력을 갖게 된다는 뜻이다. 따라서 인터넷 없이도 많은 변경 비교·커밋 작업이 가능하다. 일부 이력만 받는 옵션은 나중에 배운다. 로컬에서 기록했다는 사실과 다른 컴퓨터에 전달했다는 사실은 별개다.

Git과 GitHub를 섞으면 상태를 잘못 이해하기 쉽다. 편집기는 파일을 작성한다. Git은 변경 이력을 관리한다. GitHub는 Git 저장소를 올리고 검토·협업하는 서비스다. 별도 백업은 장치 고장이나 자료 손실에 대비한다. GitHub 계정 없이 Git을 쓸 수 있고, 로컬 커밋만 만든 상태에서는 GitHub에 새 내용이 보이지 않는다.

흐름은 `편집기 저장 → git add → git commit → git push`다. 저장은 작업 파일을 바꾼다. add는 다음 커밋에 넣을 내용을 준비한다. commit은 그 준비된 상태를 로컬 이력에 남긴다. push는 로컬 커밋을 원격에 전달한다. 네 동작을 모두 “저장”이라고 부르면 어디까지 진행했는지 알 수 없다.

## 강사 진행 장면

### 장면 1 · 최종 파일 네 개

**강사 발화:** “폴더에 `analysis.py`, `analysis_final.py`, `analysis_final2.py`, `analysis_real_final.py`가 있습니다. 이름만 보고 지난주 정상 작동한 파일을 고를 수 있나요? 단위 변환을 누가 바꿨는지는 어디서 찾을까요?”

**판서·화면:** 네 파일 이름 옆에 `현재 기준 / 바뀐 내용 / 변경 이유 / 확인 결과`를 쓴다. 실제 프로그램이 있는 것처럼 실행하지 않고 설명용 이름임을 밝힌다.

**예상 학생 답:** “이름이나 수정 날짜만으로는 부족합니다. 파일 내용을 비교하고 기록을 찾아야 합니다.”

**이어갈 설명:** “Git은 상태와 관계를 남길 수 있습니다. 좋은 변경 이유와 검증 결과는 사람이 함께 적어야 합니다. 도구를 설치한다고 맥락이 저절로 생기지는 않습니다.”

### 장면 2 · 세 줄짜리 CSV도 프로젝트다

**강사 발화:** “프로그램이 없어도 시작할 수 있습니다. 입력 파일과 그 의미를 설명한 문서만 있어도 버전을 관리할 대상입니다.”

**화면:** `samples.csv`의 `voltage_mv` 값 1000, 2000, 3000을 보여주고 README의 `Mean: 2`와 연결한다.

**예상 학생 답:** “입력은 mV이고 README의 평균은 V이므로 1000으로 나눠야 합니다.”

**이어갈 설명:** “어느 시점에 평균을 2.5로 바꿨는지는 Git으로 찾을 수 있습니다. 2와 2.5 중 무엇이 맞는지는 계산과 단위로 판단해야 합니다.”

### 장면 3 · 내 컴퓨터와 GitHub 사이

**강사 발화:** “와이파이가 끊겼습니다. 파일 수정과 커밋은 가능할까요? 원격 GitHub로 push도 가능할까요?”

**판서:** 왼쪽 `내 컴퓨터: 작업 파일·Git 이력`, 오른쪽 `원격: 공유 이력`. 두 상자 사이에 push 화살표를 그린다.

**예상 학생 답:** “Git이 설치된 로컬 저장소에서는 수정과 커밋이 가능합니다. 인터넷을 통한 원격 전송은 연결이 필요합니다.”

**이어갈 설명:** “Git은 로컬에서도 작동합니다. 다만 내 컴퓨터 한 대에만 있는 기록은 그 장치가 사라졌을 때의 대비책이 충분하지 않습니다.”

### 장면 4 · 완료했다는 말 구체화

**강사 발화:** “‘다 했어요’ 대신 지금 확인한 일을 말해봅시다. 파일 저장, 커밋 생성, 원격 반영, 계산 검증 중 무엇을 확인했나요?”

**화면:** 네 동작을 각각 다른 체크 항목으로 쓴다. 학생이 사용하는 GUI에서도 변경·스테이징·커밋·동기화가 어디에 대응하는지 찾게 한다. 아직 도구가 정해지지 않았다면 버튼 이름을 외우게 하지 않는다.

**예상 학생 답:** “파일 저장만 했습니다. 아직 커밋 여부와 원격 반영은 확인하지 않았습니다.”

## 함께 풀 사례 · 숫자를 남기는 일과 숫자를 검증하는 일

이 사례는 [연속 실습 1](../practice.md)의 입력이다. 아래 명령은 다음 단원에서 새 연습 저장소를 만든 뒤 실행한다. 현재 프로젝트나 개인 연구 저장소에서 그대로 실행하지 않는다.

```csv
time_ms,voltage_mv
0,1000
1000,2000
2000,3000
```

README 초기 내용:

```text
# Measurement notes

Unit: V
Mean: 2
```

```shell
git status
git add README.md samples.csv scratch.txt .gitignore
git diff --staged
git commit -m "docs: record sample data and expected mean"
git log --oneline
```

전제는 `scratch.txt`와 `.gitignore`까지 실습 1대로 준비된 상태다. 기대 결과는 첫 커밋 하나다. 실제 해시·날짜·출력 문장은 환경마다 달라지므로 교재가 임의 해시를 정답으로 주지 않는다. 학생은 자신의 실행에서 커밋을 찾아 기록한다.

독립 검증은 `(1000 + 2000 + 3000) / 3 / 1000 = 2V`다. 평균을 잘못 적어도 commit 자체는 성공할 수 있다. Git이 기록하는 파일과 그 파일의 과학적 타당성을 분리해 설명한다.

## 학생 활동 · 상황을 동작으로 번역하기

1. 종이에 `작업 파일 / 다음 커밋 후보 / 로컬 이력 / 원격` 네 칸을 만든다.
2. “README를 편집기에서 저장했다”를 해당 칸에 놓는다.
3. “다음 기록에 README만 넣기로 했다”를 add와 연결한다.
4. “변경 이유와 함께 로컬 이력에 남겼다”를 commit과 연결한다.
5. “팀원이 원격에서 새 커밋을 가져갈 수 있게 보냈다”를 push와 연결한다.
6. “평균이 맞다”의 근거가 위 네 칸 중 어디에 있는지 토론한다. 별도의 손계산·검증 자료가 필요함을 적는다.

**풀이 기준:** 네 동작을 순서대로 구별하고, 커밋 이전의 모든 저장이 자동으로 남는다고 말하지 않아야 한다. “GitHub가 없어서 commit 불가”, “push가 계산 정확성을 보증” 중 하나라도 남으면 역할 구분을 다시 설명한다.

## 자주 나오는 질문

- **Git은 코딩한 파일만 관리하나요?** 문서·설정·작은 데이터도 가능하다. 큰 데이터, 비밀값, 재생성 파일은 별도 정책이 필요하다.
- **저장하면 이전 내용이 전부 남나요?** 아니다. 커밋하거나 따로 보관하지 않은 내용의 복구를 보장하지 않는다.
- **커밋 하나마다 파일 하나인가요?** 한 목적의 변경이라면 여러 파일이 함께 들어갈 수 있다.
- **GitHub에 올리면 누구나 보나요?** 공개 범위와 권한에 따라 다르다. private도 외부 서비스로 전송하는 일이므로 연구 자료의 반출 조건을 따로 확인한다.
- **명령행만 써야 하나요?** GUI도 가능하다. 이번 강의는 동작을 정확히 대응하기 위해 명령행을 기준으로 설명한다.

## 통과 기준과 다음 단원

학생이 Git을 “분산 버전 관리 시스템”으로 정의하고, 네 동작의 차이를 자기 파일 예로 설명한다. 계산 정확성의 근거를 Git 성공 메시지와 분리하면 통과다. 다음 [02 · 작업 상태](02-working-state.md)에서 실제 폴더를 만들고 세 영역을 확인한다.
