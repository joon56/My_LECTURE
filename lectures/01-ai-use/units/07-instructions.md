# 단원 7 · 프로젝트 지침으로 반복되는 작업 약속 정하기

## 강의 목표와 준비

이번 요청·반복 지침·현재 상태·실제 권한을 구별한다. 강사는 프로젝트 지침 예시와 정상·누락값 사례로 확인 가능한 규칙의 형태를 설명한다.

> [!NOTE]
> **PDF 연결 | 교정 후 활용**
> 물리적 38–41쪽의 에이전트 순환·하네스·지침 파일 구성을 장면 1의 역할 구분과 장면 2의 파일 작성으로 바꾼다. 원문의 프로젝트 개요·행동 규칙·품질 기준은 유지한다. `AGENTS.md`, 정확한 `CLAUDE.md` 파일명, 최신 로딩 조건, 검증 절차는 공식 문서로 보완한 내용이다. 지침을 쓰는 것과 권한·자동 실행을 강제하는 일을 구별한다.

## 개념 설명 · 무엇을 계속 기억시킬 것인가

프롬프트에는 이번 목표를 적는다. 프로젝트 지침에는 반복해서 지켜야 하는 작업 약속을 적는다. 상태 문서에는 지금 어디까지 왔는지 적는다. “이번에는 축 이름을 고쳐줘”, “원본 데이터는 보존해”, “그래프 작성은 아직 미완료”는 서로 수명이 다르다. 이를 한 파일에 계속 쌓으면 오래된 진행 정보가 현재 규칙처럼 읽힐 수 있다.

하네스는 에이전트가 일하는 환경이다. 지침뿐 아니라 사용할 도구, 권한, 실행 결과, 상태 관리, 검사와 복구가 포함된다. “삭제하지 마”라는 문장은 행동을 요청한다. 읽기 전용 권한은 도구가 할 수 있는 작업을 제한한다. 자연어 지침을 권한 장치와 동일하게 설명하지 않는다.

## 장면 1 · 같은 부탁을 반복하는 이유 찾기

**강사 대본**

“우리는 매번 ‘한국어로 설명해’, ‘원본은 건드리지 마’, ‘실행한 결과만 성공이라고 해’라고 말할 수 있습니다. 반복되는 약속을 파일에 두면 빠뜨릴 가능성을 줄일 수 있습니다. 먼저 약속이 실제 과제에 필요한지 따져봅시다. 지침이 길수록 좋은 것은 아닙니다. 서로 충돌하거나 지금 작업에 관계없는 규칙은 판단을 어렵게 만듭니다.”

**판서·시연**

세 문장을 아래 표처럼 분류해 설명한다.

| 문장 | 둘 위치 | 이유 |
|---|---|---|
| 오늘 평균 계산까지만 구현한다 | 이번 요청 | 이번 작업 범위 |
| 원본을 보존하고 결과는 별도 저장한다 | 프로젝트 지침 | 반복되는 정책 |
| 평균 2V 확인, 오류 입력 검증 미완료 | 상태 문서 | 다음 작업의 현재 위치 |

**학생 질문**: “모든 내용을 지침에 넣으면 더 잘 기억하지 않나요?”

**예상 답**: 읽힐 분량과 관련성, 오래된 정보 문제가 생긴다. 지침은 시작 시 읽을 상태 문서의 위치를 안내하고 세부 기록은 필요할 때 읽게 한다.

## 장면 2 · 행동과 증거가 있는 지침 쓰기

**강사 대본**

“‘최고 품질로 작업하라’는 말만으로는 끝난 상태를 판단하기 어렵습니다. CSV가 잘못됐을 때 무엇을 할지, 결과를 어디에 둘지, 검증 보고에 무엇이 있어야 할지를 씁니다. 규칙을 추가할 때마다 이 규칙이 예방하는 실패를 하나 말할 수 있어야 합니다.”

**설명용 폴더 설계**

```text
measurement-practice/
├── AGENTS.md        Codex 프로젝트 지침 예
├── STATUS.md        현재 위치
├── requirements.md  입력·출력·오류 정책
├── data/            원본 입력
└── results/         생성 결과
```

Claude Code용으로는 같은 규칙을 `CLAUDE.md`에 둘 수 있다. 두 파일을 무조건 복제해 관리하라는 뜻은 아니다. 한 도구부터 시작하고, 함께 사용할 때 공유 방식과 로딩을 확인한다.

**완성된 본문 예**

```markdown
# 측정 CSV 프로젝트

목표: CSV를 검증하고 ms→s, mV→V로 변환해 요약한다.

## 시작

- requirements.md와 STATUS.md를 읽고 현재 파일과 비교한다.
- 단위나 오류 정책이 없으면 추측하기 전에 확인한다.

## 작업

- data/의 원본은 보존하고 생성 결과는 results/에 둔다.
- 누락값·비숫자·중복 시간은 위치와 이유를 보고한다.
- 사용자 가설과 확인된 사실을 구별한다.
- 이번 요청에 필요한 부분부터 작게 변경한다.

## 검증과 종료

- 정상 입력과 오류 입력을 실행하고 예상 결과와 대조한다.
- 실행하지 못한 검사는 미검증으로 표시한다.
- 변경 파일, 선택 이유, 검증 결과, 남은 문제를 기록한다.
```

**학생 질문**: “항상 질문하라고 쓰면 안전한가요?”

**예상 답**: 무엇이 중요한 미정 사항인지 정한다. 단위·삭제 정책처럼 결과를 바꾸는 조건은 확인하고, 이미 명세에 답이 있으면 읽고 진행한다. 매 단계 허가를 받게 만드는 규칙은 필요 이상의 중단을 만들 수 있다.

## 장면 3 · Codex와 Claude Code에서 읽히는 위치 확인

**강사 대본**

“파일 내용이 같아도 읽는 프로그램이 다르면 탐색 규칙이 다를 수 있습니다. 먼저 어떤 도구를 어느 폴더에서 시작했는지 확인합니다. 인터넷 예시의 경로를 내 전역 설정에 그대로 붙이지 않습니다. 프로젝트 지침은 해당 연습 폴더에 한정하는 예로 설명합니다.”

**공식 문서 확인, 로컬 실행 미검증 — 기준일 2026-10-03**

| 항목 | Codex | Claude Code |
|---|---|---|
| 대표 프로젝트 파일 | `AGENTS.md` | `CLAUDE.md` |
| 사용자 범위 예 | 기본 Codex home의 `AGENTS.md` | `~/.claude/CLAUDE.md` |
| 확인 방법 | 시작 위치·적용 지침과 실제 행동 확인 | `/context`의 파일 정보와 실제 행동 확인 |

Codex는 프로젝트 경로상의 지침과 `AGENTS.override.md` 같은 규칙을 사용한다. 구체적 탐색·우선순위는 [Codex 지침 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)에서 확인한다. 학생 폴더에 알 수 없는 상위 지침이 있으면 먼저 읽고 적용 범위를 살핀다.

Claude Code의 `AGENTS.md` 직접 지원은 v2.1.277 이상에서 문서화되어 있으며, `CLAUDE.md` 존재 여부와 설정·세션 조건에 따라 달라진다. 함께 읽는다고 가정하지 않는다. 필요한 경우 공식 문서는 같은 폴더의 `CLAUDE.md`에서 `@AGENTS.md`를 import하는 방법을 설명한다. 이 설정 예를 현재 프로젝트에 설치했다는 뜻은 아니다. 정확한 조건은 [Claude Code memory](https://code.claude.com/docs/en/memory)를 따른다.

**학생 질문**: “AI가 읽었다고 답하면 확인 끝인가요?”

**예상 답**: 자기 보고만으로 충분하지 않다. 파일의 실제 위치, 호스트의 표시·로그, 관련 입력에서의 행동을 함께 본다. 내용을 말할 수 있다는 사실과 규칙을 계속 지킨다는 사실도 다르다.

## 장면 4 · 규칙을 작은 사례로 검사하기

**강사 대본**

“이 지침이 필요한 이유는 누락값을 조용히 지우는 실수를 막기 위해서였습니다. 그러면 정상 파일만 주어서는 그 규칙을 확인할 수 없습니다. 누락값이 하나 있는 작은 입력을 준비합니다. 자동 삭제 없이 위치를 보고하고, 정상 요약을 성공처럼 출력하지 않는지 봅니다.”

**입력**

```csv
time_ms,voltage_mv
0,1000
1000,
2000,3000
```

**요청**

```text
프로젝트 지침과 requirements.md를 확인하고 이 CSV를 검토해줘.
실제로 수행한 검사와 실행하지 못한 검사를 구별해 보고해줘.
```

**기대 결과 명세**: 데이터 2행의 `voltage_mv`가 비어 있음을 보고한다. 헤더를 포함하면 파일 3행이므로 위치 기준을 함께 적는다. 누락값을 삭제·보간하지 않는다. 원본을 보존한다. 오류 상태를 정상 평균 계산 완료로 기록하지 않는다. 아래 문장은 예상 보고 형식이며 실제 실행 로그가 아니다.

```text
입력 오류: 데이터 2행 / 파일 3행 / voltage_mv 누락
자동 보정: 수행하지 않음
정상 요약: 생성하지 않음
실행 증거: 수업에서 실제 명령·결과를 채울 것
```

## 오개념과 강의 요점

- 지침 파일이 접근 권한을 바꾼다 → 접근 제한은 호스트와 도구 설정이 담당한다.
- 모든 프로젝트에 같은 긴 지침이 최선이다 → 반복되는 실제 실패에 맞춰 짧게 유지한다.
- 지침 작성 후 자동 기록이 보장된다 → 기록 수행과 파일 갱신을 확인해야 한다.

강의 요점: 좋은 지침은 필요한 행동과 확인 기준을 담는다. 파일 작성과 실제 적용을 구별한다.
