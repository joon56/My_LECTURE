# 도구 준비 · 실제 에이전트 위임 확인

공식 문서 확인일: 2026-10-04. **학생별 계정·설치·하위 에이전트 실행은 미검증**이다. 아래는 강사가 수업 전에 확인할 절차와 학생의 관찰 기준이다. API 키·새 프레임워크·MCP 서버 설치는 기본 준비물이 아니다.

## 1 사용할 환경 하나 고르기

Codex 또는 Claude Code 중 파일을 읽고 쓸 수 있는 사용 가능한 환경 하나를 고른다. CLI를 이미 쓰는 경우 터미널의 `codex --version` 또는 `claude --version`으로 버전을 기록한다. 명령이 없으면 자동 설치하지 말고 현재 앱의 도움말·버전 표시와 강사의 준비 환경을 확인한다.

각 상황의 A 또는 B 폴더를 작업 위치로 연다. 세 입력 파일이 실제로 보이는지 확인한다. 파일 접근이 없는 채팅이면 내용을 첨부·붙여넣고 반환된 내용을 사람이 파일로 저장한다. 이 경우 저장 주체를 기록한다.

## 2 Codex에서 하위 작업 확인

[공식 Subagents 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)는 독립된 일을 하위 에이전트에 명시적으로 위임하고 결과를 모으는 흐름을 설명한다.

- S02에서는 학생 또는 강사 프롬프트에 하위 에이전트 두 개의 실제 생성을 명시한다. 역할 이름만 나열한 글이 출력됐다고 생성 성공으로 보지 않는다.
- 지원되는 앱에서는 하위 작업 스레드·활동을 연다. CLI에서는 공식 문서의 `/agent`로 작업 스레드를 확인할 수 있다. 화면·명령이 다르면 설치 버전 도움말을 확인한다.
- 각 작업의 식별자 또는 표시 이름, 맡긴 질문, 실제 읽은 자료, 반환 결과, 실패 여부를 기록한다. 식별자가 표시되지 않으면 그 항목은 미확인으로 둔다.
- 하위 작업 결과를 모두 받은 뒤 총괄이 통합하는지 확인한다. 전역 설정·모델을 임의로 바꾸어 비교 조건을 달리하지 않는다.

## 3 Claude Code에서 하위 작업 확인

[공식 Subagents 문서](https://code.claude.com/docs/en/sub-agents)는 하위 에이전트의 분리된 작업과 명시적 호출, 프로젝트 범위의 역할 정의를 설명한다.

- S02 프롬프트에서 서로 다른 두 조사 업무를 실제 하위 에이전트에 맡기도록 요청한다. 표시된 하위 작업 호출·작업 내용·반환을 확인한다.
- `/agents`의 화면과 기능은 버전에 따라 달라진다. 항상 생성 마법사가 뜬다고 가정하지 않는다. 현재 도움말과 호출 기록으로 확인한다.
- 역할을 파일로 유지하는 확장은 `.claude/agents/`의 프로젝트 범위 정의를 사용할 수 있다. 기본 실습은 자연어 위임으로 시작하고, 사용자 정의 역할 설치는 별도 선택이다.
- 역할 이름만 붙인 한 응답, 한 세션에서 순서대로 말투를 바꾼 답은 독립된 하위 에이전트 실행 증거가 아니다.

## 4 지원되지 않을 때의 수동 중계

1. S02 A/B 모두 같은 대체 방식을 선택한다.
2. 별도 대화 두 개를 열고 각 대화에 공통 발주서와 담당 자료만 전달한다.
3. 학생이 두 결과를 총괄 대화로 복사하고 통합을 요청한다.
4. “수동 역할 분담·중계”로 기록한다. 실제 하위 에이전트 호출은 미수행이다.

수동 중계에서도 업무 분해·지시·결과 통합은 연습할 수 있다. 호스트의 자동 위임 기능까지 배웠다고 표시하지 않는다. 한쪽은 자동 위임, 다른 쪽은 수동 중계라면 조건 차이를 별도로 분석한다.

## 5 Markdown 지침과 실제 실행 구분

| 남길 것 | 역할 | 이번 실습에서 확인할 것 |
|---|---|---|
| AGENTS.md / CLAUDE.md | 프로젝트에 반복 적용할 규칙 | S07의 out/ 파일은 초안. 존재만으로 로딩 완료라고 하지 않음 |
| 작업별 요청문 | 지금 맡길 목표·자료·범위·완료 기준 | 저장한 문구와 실제 보낸 요청 일치 |
| 하위 에이전트 작업 | 분리된 맥락에서 맡은 일 수행 | 실제 생성·입력·반환·통합 기록 |
| SKILL.md | 필요할 때 재사용할 절차 | 반복 검토 절차가 생긴 뒤 선택 확장. 지침·권한·에이전트 정의와 구별 |
| STATUS.md | 현재 결과·미확인·다음 행동 | 파일·도구 결과와 내용 대조 |

S07 이후 자신의 최종 제작 폴더에 지침을 적용하려면 초안을 읽고 사용할 도구의 프로젝트 루트에 맞는 이름으로 복사한다. 새 세션에서 읽힌 파일·범위를 확인하고 실제 행동을 대조한다. 같은 이름의 전역 지침을 덮어쓰지 않는다. 이 검사는 A/B 비교 뒤 수행한다.

## 6 발행까지 가는 범위

기본 완료물은 로컬 article.md·post.html과 출처·검토·인계 기록이다. 기존 블로그 계정이 준비됐다면 학생이 게시 화면에 옮기고 제목·본문·코드·링크·공개 범위를 확인한 뒤 직접 게시할 수 있다. 게시 URL을 새로 열어 확인한 경우에만 발행 완료로 기록한다. 플랫폼·로그인이 준비되지 않으면 발행 대기로 남긴다.

GitHub 기록·push는 챕터 2의 Git 기초 이후 연결할 수 있다. 자동 게시 플러그인 설치는 이번 공통 비교의 완료 조건이 아니다.
