# 함께 입력하는 블로그 회사 프롬프트

강사와 학생이 아래 요청문 **한 개**를 함께 입력한다. 목표는 총괄이 실제 하위 에이전트 3개의 결과를 전달하고 글을 완성하는 과정을 보는 것이다.

## 입력 전에

새 blog-company 폴더에 [BRIEF.md](materials/blog/BRIEF.md)와 agents/ 폴더의 역할 지침 3개를 복사한다. 역할 파일은 [조사](materials/blog/agents/researcher.md)·[집필](materials/blog/agents/writer.md)·[검토](materials/blog/agents/reviewer.md)다. AI 작업 위치를 그 폴더로 연다. 폴더 준비·수업 흐름은 [실습 교안](practice.md), 도구 확인은 [강사 환경 안내](materials/blog/TOOLS.md)를 따른다.

## 공통 프롬프트

```text
현재 폴더의 BRIEF.md를 읽고 블로그 글 한 편을 만드는 작은 회사를 운영해줘.
너는 총괄이다. 실제 하위 에이전트는 조사·집필·검토 3개만 사용해.
실제 생성 기능이 없으면 지원되지 않는다고 알리고 멈춰줘.

시작 전에 아래 역할 지침 3파일이 있는지 확인해.
각 담당에게 자기 지침 파일과 BRIEF.md의 절대 경로를 전달하고,
두 파일을 직접 읽은 뒤 작업하도록 요청해. 읽지 못하면 중단해.
이 파일들은 이번 요청에서 명시적으로 읽는 Markdown 지침이다.

1. 조사 담당: agents/researcher.md와 BRIEF.md를 읽게 해.
   주장·근거·한계를 돌려받은 뒤 다음 담당으로 넘어가.
2. 집필 담당: agents/writer.md와 BRIEF.md를 읽게 하고,
   실제 조사 결과를 메시지로 전달해 초고를 받아.
3. 검토 담당: agents/reviewer.md와 BRIEF.md를 읽게 하고,
   실제 초고를 메시지로 전달해 검토 의견을 받아.
4. 수정이 필요하면 같은 집필 담당에게 실제 검토 의견을 전달해 한 번 보완해.
   총괄이 반영 여부를 확인하고 남은 문제를 밝혀줘.

각 위임 전에 “읽을 지침 → 담당 → 받을 결과”를 한 줄로 알려줘.
반환 뒤에는 실제로 읽은 파일과 다음 담당에게 넘기는 결과를 알려줘.
담당의 읽었다는 보고와 도구의 파일 읽기 기록을 구분해.
기록을 확인할 수 없으면 파일 읽기 검증은 미확인으로 적어줘.

하위 담당은 응답으로 결과를 반환하고 파일은 총괄만 저장해.
입력 파일과 역할 지침을 보존하고 article.md에 최종 원고만,
work.md에 담당·읽은 지침·전달·실제 수정·남은 확인을 짧게 남겨줘.
각 결과가 오기 전에 다음 단계가 완료됐다고 쓰지 마.
필수 수정이 없으면 없다고 하고 불필요한 수정을 만들지 마.
실패하면 어느 담당의 어느 단계에서 멈췄는지 알려줘.
제공 자료만 사용하고, 열지 않은 원문·실행하지 않은 코드·게시를 완료했다고 쓰지 마.
추가 에이전트·웹 검색·도구 설치·HTML 제작·블로그 업로드는 하지 마.
```

## 강사가 설명할 세 지점

1. **역할 파일 읽기:** “BRIEF는 이번 글의 의뢰서, agents/의 파일은 담당별 업무 지침, 프롬프트는 총괄의 진행 순서입니다.” 폴더에서 researcher.md를 열고 조사 작업의 실제 파일 읽기 기록과 연결한다. 같은 방식으로 집필·검토 지침을 가리킨다.
2. **결과 전달:** 조사 반환→집필 입력, 초고→검토 입력, 검토 의견→집필 보완을 가리킨다. 이 시연에서는 총괄이 중계한다.
3. **마무리:** article.md와 work.md를 직접 연다. 계산 반례 하나와 실제 전달·수정 한 가지를 확인하고 끝낸다.

프롬프트를 먼저 설명한 뒤 학생과 함께 실행한다. 상대 점수나 프롬프트 우열을 측정하지 않는다. 문장이 길거나 에이전트가 많아서 좋은 것이 아니라 맡길 일·자료·받을 결과·순서를 명확히 한 점을 짚는다.

## 예상과 막힘

예상은 실제 하위 작업 세 개의 반환과 최종 두 파일이다. 생성 여부는 도구 화면과 파일로 확인한다. 반환 내용은 모델 실행마다 다를 수 있다. 검토가 문제를 발견하지 않으면 수정 과정을 억지로 만들지 않는다.

학생 환경이 미지원이면 강사 화면으로 관찰한다. 강사도 미지원이면 실제 위임 시연은 미수행이다. 실패한 작업을 자동으로 계속 재시도하거나 추가 역할을 만들지 않는다. 새로운 활동이 필요하면 강사가 범위를 정한 뒤 별도로 진행한다.

이 요청문은 교육용이며, 학생 환경에서의 실제 동작은 수업 전 리허설로 확인한다.

역할 파일은 이번 요청에서 경로를 지정해 읽게 하는 일반 Markdown이다. Codex·Claude Code가 자동 등록하는 설정 파일로 설치한 것은 아니다. 파일 생성, 하위 작업 생성, 실제 파일 읽기를 각각 구분해서 설명한다.
