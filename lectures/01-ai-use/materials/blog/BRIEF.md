# 블로그 회사 · 공통 작업 자료

자료 버전: 2026-10-04 역할 파일 분리본. 이 파일은 모든 담당이 공유하는 글의 요구사항과 근거 자료다. 담당별 작업 지침은 agents/의 세 파일에 있다.

## 만들 글

- 제목: **AI가 만든 코드는 실행만 되면 믿어도 될까?**
- 독자: AI로 프로그램 과제를 해본 공대 후배.
- 한국어로 짧은 블로그 글 한 편. 소제목 3개 안팎으로 설명하고 분량을 따로 채점하지 않는다.
- 아래 반례와 출처를 사용한다. 새 통계·가짜 실행 경험을 만들지 않는다.
- 최종 파일: article.md(검토를 반영한 글), work.md(역할별 작업·전달·수정·남은 확인을 짧게 정리).

## 사용할 반례

교육용으로 만든 계산 사례다. 실제 연구실 데이터가 아니다.

```python
voltage_mv = 1000
print(voltage_mv / 100)
```

위 계산의 값은 10이다. 단위 정의상 1000 mV는 1 V이므로 V 변환은 1000으로 나눠야 한다. 오류 없이 숫자가 출력돼도 단위 변환은 틀릴 수 있다. 직접 실행하지 않았다면 계산으로 확인했다고 표현한다.

## 출처 요약

2026-10-04 교재 작성 시 확인한 공식 문서의 요약이다. 학생이나 에이전트가 원문을 직접 조회했다는 기록은 아니다. 실습에서는 이 요약을 읽으며 추가 검색은 하지 않는다.

- **GitHub Copilot Chat:** 생성된 코드는 사람이 검토하고 테스트해 요구사항에 맞는지 확인해야 한다. 생성된 테스트가 모든 상황을 다룬다고 가정하지 않는다. [공식 문서 · Best practices](https://docs.github.com/en/copilot/responsible-use/chat).
- **Python 3.12 assert:** 최적화 옵션 `-O`에서는 assert 코드가 생략될 수 있다. “assert를 넣었으니 모든 실행에서 검사한다”라고 쓰지 않는다. [공식 문서 · 7.3](https://docs.python.org/3.12/reference/simple_stmts.html#the-assert-statement).

글에는 실행 성공과 정확성의 차이, 단위 변환 반례, 사람이 확인할 행동을 설명한다. 예시 행동은 입력·단위 확인과 손계산 예상값 대조다. 몇 가지 확인만으로 모든 오류가 없다고 보장하지 않는다.

## 이번 범위

제공 자료를 읽어 글 한 편을 만든다. 입력 파일을 보존하고 현재 폴더에 article.md·work.md만 저장한다. 추가 하위 에이전트·웹 검색·도구 설치·블로그 업로드는 하지 않는다. 실제 하위 작업이 지원되지 않으면 그 사실을 알리고 멈춘다. 역할 이름만 붙여 실제 위임을 수행했다고 보고하지 않는다.
