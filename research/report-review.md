# 좋은 프롬프트 보고서 검토와 강의 반영안

검토일: 2026-10-03. 대상: 유민준_최종보고서.pdf, 물리적 49페이지. 본문·참고문헌 텍스트 전체를 읽고, 주요 도식과 출력 예시, 이미지로 된 부록 47~49페이지를 렌더링해서 확인했다. 아래 페이지는 PDF 뷰어의 순서다. 원본은 수정하지 않았다.

## 총평

보고서는 이미 문제 정의→기대 기준→위임→피드백→반복이라는 실무 뼈대와 에이전트·하네스까지 담고 있다. 새 강의는 이 구조에 실제 파일, 도구 실행, 검증 증거, 작업 인계를 붙이면 된다.

보완의 중심은 두 가지다. 첫째, 연구의 관찰 결과를 모든 모델에 통하는 법칙처럼 설명하지 않기. 둘째, 학생이 원리를 듣고 나서 구체적으로 어떤 행동을 할지 연결하기.

## 우선 교정할 내용

### 1 입력 품질이 출력 품질을 결정한다는 표현

- 위치: 1, 8, 10, 42~44쪽.
- 문제: 입력이 출력에 영향을 준다는 메커니즘으로부터 특정 프롬프트 기법의 우월성이나 성공 보장이 바로 따라오지는 않는다.
- 권장 표현: “목적과 관련 정보를 명확히 주면 원하는 결과를 얻을 가능성을 높일 수 있다. 결과는 모델 능력, 제공 자료, 도구, 실행 환경, 검증에도 좌우된다.”
- 교육 제안: 좋은 요청과 충분한 자료를 줘도 틀리는 예시를 함께 보여준다. 실패를 항상 학생의 질문 탓으로 돌리지 않는다.

### 2 Transformer 설명에 적용 범위 표시

- 위치: 5~10쪽.
- 문제: 원논문의 encoder-decoder, 사인·코사인 위치 인코딩은 역사적 구조 설명이다. 현대 모든 제품의 공개된 내부 구조를 뜻하지 않는다. 자기어텐션의 병렬 처리와 자기회귀 생성 순서도 구분해야 한다.
- 권장 내용: GPT형 causal decoder의 각 위치는 허용된 앞선 문맥을 참조한다. 학습 시 알려진 시퀀스를 병렬 처리하는 것과 응답을 순서대로 생성하는 것은 다른 단계다.
- 강의 처리: 토큰→문맥→생성→도구 결과 반영을 본문에 두고 Q/K/V 수식과 구조 역사는 심화 자료로 둔다.
- 근거: [Attention Is All You Need](https://arxiv.org/abs/1706.03762). 이 논문만으로 현재 비공개 모델의 구현을 단정하지 않는다.

### 3 학습 단계의 설명은 대표 사례로 한정

- 위치: 8~10쪽.
- 문제: 사전학습→지도 미세조정→RLHF의 세 단계가 모든 최신 모델의 동일한 훈련 순서라고 받아들여질 수 있다.
- 권장 표현: “대표적인 지시 학습 과정을 설명한 사례다. 실제 모델의 후속 학습과 추론 방식은 제품과 모델에 따라 달라진다.”
- 실무 연결: 대화 중 문서를 읽는 것, 앱이 기억을 저장하는 것, 모델 가중치를 학습하는 것은 구분한다. 문서나 지침을 읽었다고 새 모델을 훈련한 것은 아니다.

### 4 CoT를 모든 모델의 기본 요청으로 권장하지 않기

- 위치: 13, 23~26쪽.
- 문제: 과거 연구에서 효과를 보인 “단계적으로 생각하라”를 최신 추론 모델에도 항상 유리한 방법으로 전할 수 있다. 최종 답을 짧게 받는다고 내부 계산이 한 번의 단순한 선택으로 끝난다고 단정할 수도 없다.
- 권장: 학습용 풀이 설명은 요청할 수 있다. 실무에서는 목표, 제약, 완료 기준, 계산·출처·검증 결과를 요청한다. 내부 추론 전체를 요구하는 방식을 기본 템플릿으로 삼지 않는다.
- 근거: [OpenAI reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)는 추론 모델에 직접적이고 명확한 지시를 권장하며 CoT 유도가 불필요할 수 있다고 설명한다. 이 권고도 해당 모델 유형에 대한 안내다.

### 5 출력 형식 지정과 few-shot 구분

- 위치: 11~12, 29쪽과 부록.
- 문제: 항목과 순서를 지정하는 일을 few-shot 구조라고 설명한다. 입력과 기대 출력의 완성 예시가 없는 형식 지정은 few-shot 예시 제공과 다르다.
- 교정: 항목·길이·표기 지정은 출력 형식 지시. 실제 입력과 원하는 출력 쌍을 예제로 제시하는 것은 예시 기반 요청.
- 실습: 같은 CSV 검증 과제를 자유 요청, 형식 지정, 예시 추가의 세 버전으로 작성한다. 형식 준수와 사실 정확성을 따로 평가한다.
- 근거: [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering).

### 6 좋은 출력 예시에서도 수치 오류 발견

- 위치: 29쪽 그림 6, 부록의 대응 화면.
- 관찰: 영→불 번역 결과가 BLEU 41.0으로 보인다. 원논문 초록의 결과는 41.8이다.
- 교정: 본문과 실제 출력을 대조한 표에 오류를 명시한다. “구조와 독자 적합성 개선”을 “정확성 확보”로 바꾸어 말하지 않는다.
- 활용: 학생에게 먼저 보기 좋은 출력을 평가하게 한 뒤, 원논문과 수치 대조를 시킨다. 형식이 좋아도 사실 오류가 남는다는 강의 도입 사례로 적합하다.
- 근거: [원논문 초록](https://arxiv.org/abs/1706.03762). 원출력의 전체 텍스트나 실행 로그는 제공되지 않아 모델·실행 설정의 재현은 확인하지 못했다.

### 7 MECE와 작업 독립성 구분

- 위치: 19~20쪽.
- 문제: 중복 없이 빠짐없이 나누면 각 작업이 서로 영향을 주지 않는다고 설명한다. 분류 기준과 실행 의존성은 다르다.
- 교정 예시: 파일 읽기, 단위 변환, 그래프 작성은 구분되지만 그래프는 변환 결과에 의존한다.
- 실무 연결: 분해 후 입력·출력·선행 작업을 적는다. 동시에 맡길 일은 파일과 인터페이스 충돌까지 확인한다. 여러 에이전트를 쓰는 판단에도 같은 기준을 적용한다.
- 성격: 논리적 교정 및 강의 설계 제안.

### 8 결정론적 작업은 검증한 코드로 실행

- 위치: 21~22쪽.
- 문제: 규칙 기반 업무를 “모델이나 코드로 대체”한다고 묶으면 반복 계산도 매번 자연어 생성에 맡겨도 된다고 읽힐 수 있다.
- 권장: AI를 사용해 코드를 만들고, 예상값과 비교한 뒤 반복 계산은 그 코드를 실행한다. 날짜·단위·집계 결과는 계산 도구의 결과로 확인한다.
- 위임 기준 보완: 검증 가능성, 반복성, 문서화 가능성에 오류 영향과 복구 가능성을 더한다.
- 성격: 공학 실습을 위한 교육 제안.

### 9 2025년과 2026년 논문의 주장 연결 수정

- 위치: 3, 16, 33쪽과 45~46쪽 참고문헌.
- 관찰: 3쪽에서 소개한 2026년 논문이 참고문헌에 없다. 불충분한 지시와 관련 토큰 값의 관계를 16·33쪽에서는 Errica 외(2025)와 연결한다.
- 확인: 해당 서술에 직접 대응하는 연구는 Pecher, Spiegel, Belanec, Cegin의 2026년 텍스트 분류 연구다. 연구는 관련 label token의 logit 및 출력 민감성을 분석한다. 이를 모델의 일반적인 사실 확신도나 할루시네이션의 직접 원인으로 확대하지 않는다.
- 조치 제안: Pecher 외(2026)를 참고문헌에 추가하고, Errica 외(2025)의 민감성·일관성 분석과 출처를 분리한다. 특정 문장의 인용을 바꿀 때 원문의 실험 범위도 함께 적는다.
- 근거: [Pecher 외 2026 원문](https://arxiv.org/html/2602.04297v1), [Errica 외 2025](https://aclanthology.org/2025.naacl-long.73/).

### 10 일관성 지표의 정답 정보 조건 수정

- 위치: 35~36쪽.
- 문제: 민감성과 일관성 모두 정답 표시 없이 계산할 수 있다고 묶었다.
- 확인: Errica 외의 민감성은 정답 라벨 없이 측정할 수 있다. 제시된 일관성 정의는 같은 클래스의 표본 집합을 사용하므로 해당 클래스 정보를 요구한다. 논문 Definition 2와 식 6~7 참조.
- 교정: 정확성과 안정성은 별도로 설명하고, 두 지표의 필요한 정보도 구분한다. 분류 지표를 모든 생성 작업에 그대로 적용하지 않는다.
- 근거: [논문 PDF](https://aclanthology.org/2025.naacl-long.73.pdf), 논문 인쇄 페이지 1546~1547.

### 11 할루시네이션을 확률적 샘플링 하나로 설명하지 않기

- 위치: 31~34, 42쪽.
- 문제: 확률적으로 생성하므로 환각이 생긴다는 설명만으로는 학습·지식의 한계, 추측을 유도하는 평가, 검색 오류, 도구 해석 오류를 설명하기 어렵다.
- 보완: 확률이 높은 문장과 근거가 맞는 문장을 구분한다. 명확한 요청, 출처 제공, 보류 허용, 도구 검증은 각각 다른 오류를 줄이는 장치다.
- 근거: [OpenAI의 환각 연구 소개](https://openai.com/index/why-language-models-hallucinate/)는 불확실성을 인정하는 것보다 추측을 보상하는 훈련·평가 문제를 분석한다. 환각의 모든 원인을 하나로 확정한 결론으로 소개하지 않는다.

### 12 사례 비교는 시연으로 유지

- 위치: 27~30, 35~37쪽.
- 보고서가 통제 실험이 아닌 시연이라고 밝힌 점은 유지한다.
- 보완: 역할, 길이, 구조, 독자 정보를 동시에 바꿨으므로 특정 요소 하나의 효과를 분리할 수 없다. 역할 지정만으로 정확성을 확보했다는 표현은 낮춘다.
- 새 실습은 동일 자료·도구 조건과 평가 기준을 먼저 정한다. 모델 표시명, 날짜, 검색 사용 여부, 원출력, 실패까지 남긴다. 적은 반복 결과를 보편적 성능 향상률로 보고하지 않는다.
- 근거: [평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

### 13 지침 파일과 실제 제어 장치 구분

- 위치: 38~41쪽.
- 보완: 지침 파일은 맥락과 작업 약속을 전달한다. 하네스에는 도구 실행, 권한, 상태 관리, 검사, 복구도 포함된다. 지침 파일 하나로 실행 제한이나 자동 기록을 보장할 수 없다.
- 실무 연결: AGENTS.md / CLAUDE.md, STATUS.md, Skill, MCP, 실제 권한과 hook의 역할을 구분한다.
- 근거: [Claude Code 메모리와 지침](https://code.claude.com/docs/en/memory), [장기 작업 하네스 사례](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents).

## 편집 보완

- `least-to-most prompting`은 “쉬운 하위 문제부터 순차적으로 해결”로 설명하면 의미가 분명하다. “최소-최대”는 min-max와 혼동될 수 있다.
- 원문에서 2022 preprint와 2023 학회 발표 연도가 섞인 문헌은 채택한 판본을 통일한다.
- 빈 “단위:” 표기, “미시”와 MECE의 표기, 장 번호 참조를 정리한다.
- 40쪽 공개 게시물 사례는 출처 URL과 게시일을 확보하기 전에는 연구 근거로 사용하지 않는다.
- 모델 표시명은 제공 자료에 적힌 값으로 취급한다. 이번 검토에서 당시 실행 환경이나 제품명을 별도 검증하지 않았다.

## 강의에 추가할 실무 역량

1. 모델·앱·에이전트·실행 환경의 구분.
2. 파일 접근과 도구의 실제 실행 여부 확인.
3. 맥락 선택, 긴 대화 요약, 작업 인계.
4. 제한된 범위로 맡기기, 오류 재현, 변경 diff 확인.
5. 프로젝트 지침과 반복 작업용 Skill의 분리.
6. MCP 연결·권한·호출 결과 확인, Plugin의 구성 요소 읽기.
7. 프롬프트 인젝션과 할루시네이션의 차이.
8. 비용·시간·재작업·검증 성공률로 작업 방식을 평가하기.
9. 사용자와 AI의 현재 이해를 맞추는 작업 기록.
