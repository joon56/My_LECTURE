# 단원 8 · 대화가 끝나도 이어지는 작업 기록과 인계

## 강의 목표와 준비

생성 완료·동작 검증·사용자 확인을 구별한다. 강사는 가상 사례의 상태 문서와 작업 기록으로 다음 세션에 필요한 목표·근거·미확인·다음 행동을 설명한다.

> [!NOTE]
> **PDF 연결 | 활용 + 새로 추가**
> 물리적 17–18쪽의 정의→기준→위임→피드백→반복을 장면 1의 기록 항목에 연결한다. 38–41쪽의 지속적 맥락·하네스는 장면 3의 새 세션 인계에 활용한다. 원문이 `STATUS.md`, 작업 기록 양식, 사용자 확인 상태를 직접 제안한 것은 아니다. 이 파일 구조와 구체적 절차는 수업을 위한 새 설계다.

## 개념 설명 · 기억 대신 다시 찾을 수 있는 상태

긴 대화에는 현재 목표, 포기한 시도, 잠정 가설, 검증 결과가 섞여 있다. 다음 세션에 대화가 충분히 전달되지 않을 수도 있고, 전달되어도 오래된 내용을 현재 사실로 오해할 수 있다. 작업 기록은 중요한 관찰과 판단 근거를 파일로 남기는 방법이다. 요약을 썼다는 이유만으로 다음 세션이 자동으로 읽는 것은 아니다.

`STATUS.md`는 지금의 위치와 다음 행동을 빠르게 찾는 입구다. 작업 기록은 한 목적을 위해 실제 수행한 변경·검증·이유를 남긴다. `DECISIONS.md`는 이후에도 영향을 주는 결정만 모을 수 있다. 파일이 세 개여야 한다는 법칙은 없다. 작은 과제에서는 한 문서 안의 절로 시작해도 된다. 규모가 커지면 현재 상태와 상세 이력을 나누는 편이 읽기 쉽다.

## 장면 1 · “끝났다”를 세 질문으로 풀기

**강사 대본**

“AI가 ‘완료했습니다’라고 했습니다. 이제 세 가지를 묻겠습니다. 파일을 만들었나요? 실행해서 기대값과 비교했나요? 사용자가 결과를 읽고 방향에 동의했나요? 셋은 독립적입니다. 파일은 있어도 실행하지 않았을 수 있습니다. 실행은 성공했어도 연구자가 요구한 의미와 다를 수 있습니다.”

**판서**

| 상태 | 판단할 증거 | 말할 수 없는 것 |
|---|---|---|
| 생성 완료 | 파일 존재·내용 확인 | 모든 동작이 맞음 |
| 검증 완료 | 명시한 입력·명령·결과·기준 | 다른 환경과 모든 입력에서도 성공 |
| 사용자 열람 확인 | 사용자가 읽었다고 밝힘 | 해당 방향에 동의 |
| 합의 | 특정 선택에 명시적 동의 | 이후 모든 세부 결과 승인 |

**학생 질문**: “사용자가 다음 질문으로 넘어가면 동의한 것 아닌가요?”

**예상 답**: 침묵·다음 질문은 전체 동의의 증거가 아니다. 다음 허용된 작업은 진행하되, 기록에는 확인된 상태만 쓴다. 사용자 확인을 기다린다는 이유로 모든 작업을 멈추게 만들 필요도 없다.

## 장면 2 · 나쁜 기록을 다시 실행할 수 있는 기록으로 바꾸기

**강사 대본**

“‘오류 수정했고 잘 됩니다’라는 기록은 내일 도움이 적습니다. 어떤 오류였는지, 어떤 입력에서 어떻게 확인했는지 빠져 있기 때문입니다. 반대로 채팅을 전부 복사하면 핵심을 찾기 어렵습니다. 입력, 실행, 관찰, 남은 검사를 골라 남깁니다. 생각의 독백을 적는 일이 아닙니다.”

**가상 작업 상황**

학생은 `src/analyze.py`를 작성했고 정상 CSV의 평균이 2V임을 확인했다. 누락값 입력은 아직 실행하지 않았다. 그래프 기능은 없다. 사용자는 “원본을 보존하자”에 동의했지만 코드는 아직 읽지 않았다. 아래 예시는 이 상황을 전제로 쓴 모범 기록이며 본 강의 제작에서 수행한 실행 로그가 아니다.

```text
measurement-practice/
├── requirements.md
├── STATUS.md
├── src/analyze.py
├── data/normal.csv
├── data/missing.csv
├── results/summary.json
└── logs/2026-10-03-01-summary.md
```

**작업 기록 예**

```markdown
# CSV 단위 변환과 평균 요약

## 요청·목표
ms와 mV를 s와 V로 변환하고 평균을 저장한다.
원본 보존은 사용자와 합의한 정책이다.

## 수행
src/analyze.py 작성. results/summary.json 생성.

## 검증 — 가상 사례에서 관찰한 것으로 주어진 내용
입력: data/normal.csv. 전압 1000, 2000, 3000mV.
명령: python src/analyze.py data/normal.csv --out results/summary.json
기대: 평균 (1 + 2 + 3) / 3 = 2V.
관찰: mean_voltage_v = 2.0. 기대값과 일치.

## 판단 이유
입력값을 V로 변환한 뒤 요약해 출력 단위를 통일했다.

## 미확인
data/missing.csv 실행 전. 그래프 미구현.
실제 장비 데이터·다른 운영체제는 검증하지 않았다.

## 사용자 확인
원본 보존 정책: 합의.
코드와 결과: 미확인.

## 다음
누락값 입력의 오류 처리부터 실행한다.
오류 입력에서 정상 요약을 새로 생성하지 않는지 확인한다.
```

**학생 질문**: “명령을 적었으면 실행했다는 뜻인가요?”

**예상 답**: 실행 계획과 관찰 결과를 구분한다. 복사해 쓸 명령만 있으면 실행법이다. 실제 검증에는 실행 시점·환경·결과가 필요하다. 수업에서는 제공된 가상 결과와 자신이 실행한 결과를 같은 칸에 섞지 않는다.

## 장면 3 · 현재 상태는 입구만 짧게 남기기

**강사 대본**

“현재 상태에는 모든 과거를 넣지 않습니다. 다음 사람이 지금 필요한 파일로 이동할 수 있게 씁니다. 그리고 기록을 읽은 다음 실제 파일을 확인합니다. 기록 이후 코드가 바뀌었다면 예전의 통과 결과로 지금 버전을 보증할 수 없습니다.”

**앞 사례의 `STATUS.md` 예**

```markdown
# 현재 상태

목표: 측정 CSV 검증·변환·요약·그래프.
현재: 단위 변환과 평균 요약 구현. 정상 샘플 평균 2V 확인.
남음: 누락값 처리 실행 검증, 그래프 구현.
합의: 원본 보존. 코드·결과 열람은 미확인.
다음: data/missing.csv로 오류 정책 검사.
근거: [요약 작업 기록](logs/2026-10-03-01-summary.md).
```

**새 대화 시작 요청**

```text
프로젝트 지침, STATUS.md, 관련 작업 기록을 읽어줘.
기록의 완료 내용과 현재 파일이 일치하는지 확인해줘.
실행한 검증과 계획만 있는 검증을 구분해줘.
이번에는 누락값 처리 검증을 이어가줘.
현재 명세로 결정할 수 없는 처리 정책만 질문해줘.
```

Codex와 Claude Code 모두 파일을 읽을 수 있는 환경이라면 같은 인계 원칙을 쓸 수 있다. `STATUS.md`는 두 제품의 공통 자동 로딩 규격이 아니다. 프로젝트 지침이나 이번 요청에서 읽을 위치를 지정하고 도구의 실제 읽기 결과를 확인한다. 메모리 기능의 존재도 현재 파일 대조를 생략할 이유가 되지 않는다.

**학생 질문**: “지난 기록과 코드가 다르면 기록을 지우나요?”

**예상 답**: 먼저 어떤 버전에 대한 관찰인지 확인한다. 이전 관찰은 역사로 보존하고 현재 상태를 갱신한다. 잘못 적은 사실이면 정정 이유와 근거를 남긴다. 유효한 과거 결과와 현재 미검증을 구별한다.

## 장면 4 · 읽어 이해했는지 확인하기

**강사 대본**

“기록이 많아도 사람이 설명할 수 없다면 교육 목표는 아직 남아 있습니다. 인계받은 사람이 원본 위치, 전압 단위, 누락값 정책, 2V의 근거를 복원할 수 있어야 합니다. 답이 없으면 더 긴 요약을 만드는 대신 필요한 파일 한 곳을 열고 작은 입력으로 다시 확인합니다.”

**시연**: 강사는 대화 창을 가리고 상태·기록·명세만 보여준다. 강사가 다음 명령의 예상 결과와 오류 입력의 실패 기준을 설명한다. 이 방식은 단순 따라치기와 이해를 구별한다.

**학생 질문**: “AI가 설명을 잘 해주면 제가 이해한 것 아닌가요?”

**예상 답**: AI 설명의 품질과 학습자의 설명 능력은 다르다. 학생이 직접 예측하고, 결과를 비교하고, 틀린 이유를 설명해야 한다.

## 오개념과 강의 요점

- 기록 파일을 만들면 자동으로 다음 세션에 전달된다 → 실제 읽기 경로가 필요하다.
- 작업 기록은 Git을 대체한다 → 이유와 상태를 설명하지만 파일 버전 복원 기능을 자동 제공하지 않는다.
- 자세한 기록은 대화 전부 보존이다 → 판단 근거와 실행 증거를 선별한다.

강의 요점: 현재 상태는 다음 행동의 입구, 기록은 관찰과 판단의 근거다. 사용자 합의를 추정하지 않는다.
