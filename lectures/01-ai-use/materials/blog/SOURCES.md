# 공통 자료 묶음 · 공식 문서 세 곳

자료 확인일: 2026-10-04. 아래는 강의 작성자가 확인한 공식 문서의 **짧은 교재 요약**이다. 원문 전문이 아니다. 학생·에이전트가 직접 조회한 것으로 간주하지 않는다. 자료를 제공받아 읽은 경우와 링크를 열어 원문을 대조한 경우를 작업 기록에서 구분한다.

## S1 GitHub · 생성된 코드의 검토와 테스트

- 문서: [Application card: GitHub Copilot Chat](https://docs.github.com/en/copilot/responsible-use/chat).
- 찾을 위치: `Best practices`의 코드 검토·테스트 권고와 테스트 생성의 한계 설명.
- 교재 요약: GitHub는 Copilot이 만든 코드를 검토하고 테스트해 요구사항과 맞는지 확인하도록 안내한다. 생성된 테스트가 모든 상황을 다룬다고 가정하지 않는다.
- 뒷받침하는 주장: AI의 제안은 별도 검토·테스트가 필요하다.
- 이 자료로 확정할 수 없는 주장: 모든 도구의 오류율, AI 검토가 인간 판단을 완전히 대체한다는 결론, 특정 프롬프트의 개선율.

## S2 Python 3.12 · assert의 실행 조건

- 문서: [7.3. The assert statement](https://docs.python.org/3.12/reference/simple_stmts.html#the-assert-statement).
- 찾을 위치: 7.3의 `__debug__`와 `-O` 설명.
- 교재 요약: assert는 조건 확인을 위한 구문이다. 문서는 최적화 옵션 `-O`를 사용하면 assert 코드가 생성되지 않는다고 설명한다.
- 뒷받침하는 주장: assert가 적혀 있다는 사실만으로 모든 실행에서 그 검사가 수행된다고 판단할 수 없다.
- 적용 범위: 여기서는 Python 3.12 문서의 동작을 설명한다. 다른 언어나 모든 테스트 도구의 특성으로 확대하지 않는다.

## S3 OpenAI · 과제에 맞는 평가 설계

- 문서: [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices).
- 찾을 위치: `Define your eval objective`, 평가 자료·지표·실행 비교·지속 평가를 설명하는 절.
- 교재 요약: 무엇을 성공으로 볼지 정한 뒤 평가 자료와 기준을 마련하고 결과를 비교·개선한다. 한 번의 좋아 보이는 출력보다 과제에 맞춘 확인을 권한다.
- 뒷받침하는 주장: 평가 목표·자료·기준을 먼저 정해 결과를 판단할 필요가 있다.
- 적용 범위: LLM 애플리케이션 평가 지침이다. 이것만으로 모든 프로그램의 무결함을 증명하는 알고리즘을 얻는 것은 아니다.
