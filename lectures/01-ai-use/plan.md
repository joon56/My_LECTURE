# 챕터 1 설계 · AI와 문제를 정의하고 구현·검증하기

운영 순서: **챕터 1 강의 전체 → 챕터 1 실습 → 챕터 2 강의 전체 → 챕터 2 실습.** 강의 사이에 학생 파일 작성·설정·제출을 끼워 넣지 않는다. 학생 활동은 [챕터 1 실습](practice.md)에 모았다.

## 목표와 대상

공대 후배가 AI의 응답을 작업 명세, 실제 파일·실행, 독립된 검사, 다음 사람에게 넘길 기록으로 연결하게 한다. Codex와 Claude Code를 모두 설명하되 실제 수행은 사용할 수 있는 도구 하나로 시작한다. 시간보다 개념의 깊이와 재현 가능한 절차를 우선한다.

핵심 흐름은 문제 정의→맥락 준비→위임→실행→검증→기록이다. 공통 블로그 주제에서 학생이 직접 요청과 업무 경계를 설계하고 결과의 근거·한계·본인 판단을 설명한다. 실제 연구실 과제를 즉석에서 정하는 활동은 이번 교안에 넣지 않는다. 학생 운영체제·계정·수준은 수업 전에 확인한다.

## 강의 예시와 실습 자료

강의의 계산 예시는 손계산 가능한 합성 전압 CSV다. CSV는 쉼표로 열을 나눈 텍스트 표이며 실제 연구 결과가 아니다. 열은 `time_ms,voltage_mv`, 행은 `0,1000`, `1000,2000`, `2000,3000`이다. s·V로 변환하면 시간 0·1·2, 전압 1·2·3, 평균 2 V다. 이 예시는 검증 원리를 설명하며 기존 CSV 자료는 보존한다.

챕터말 실습은 **「AI가 만든 코드는 실행만 되면 믿어도 될까?」**라는 같은 블로그 주제로 진행한다. 독자는 AI로 프로그램 과제를 해본 공대 1~2학년이다. 글의 요구와 평가 기준은 [BRIEF](materials/blog/BRIEF.md), 공식 자료 위치와 요약은 [SOURCES](materials/blog/SOURCES.md), 비교에 쓸 고정 사례는 [CASES](materials/blog/CASES.md)에 제공한다. 근거 자료와 교육용 제안을 구분한다.

학생은 강의 저장소 밖의 새 `blog-lab` 폴더에서 입력 파일 저장·UTF-8·확장자 확인부터 시작한다. 폴더 생성과 복사 방법은 [실습](practice.md)에 있다. 기존 파일·AI 응답·블로그 플랫폼이 준비되어 있다고 가정하지 않는다. 최종 결과는 근거 있는 원고와 로컬 HTML 한 편이다. 사람이 내용·출처·화면을 검토하고 내보내며, 기존 블로그에 직접 올리는 일은 선택이다.

## 챕터말 실습 설계

| 활동 | 산출물·확인 |
|---|---|
| 준비 | 동일 입력 사본, 독립 A/B 폴더, 도구·메모리·예산 확인 |
| S01 발주·기획 | plan.md, 입력·산출물·완료 기준·의존 관계·위임 이유 |
| S02 실제 위임·조사 | evidence.md, delegation.md, 실제 하위 작업·반환·통합 증거 |
| S03 근거로 작성 | 고정 C2 근거표에서 article.md 작성, 주장·출처·한계 대조 |
| S04 검토·동조 대응 | C3의 같은 결함·의뢰 문장, review.md와 corrected.md |
| S05 디자인·미리보기 | C4를 post.html로 변환, 사람이 화면·링크 확인 |
| S06 조건 변경 | C4+C5에서 수정 계획·원고, 재사용·선택 재실행 판단 |
| S07 지침·인계 | C6에서 AGENTS.md 또는 CLAUDE.md 초안, STATUS·재개 요청 |
| 최종 연속 제작 | 자기 프롬프트·실제 앞 단계 결과로 글 한 편, 사람 검사·내보내기 |

각 상황은 **학생 자작 프롬프트 A→원응답 저장·판정→강사 masterpiece prompt B 공개→동일 입력의 새 세션에서 실행→비교→자기 개선문 C** 순서다. 학생은 업무 경계·위임문·검사·재작업을 직접 결정한다. 강사 완성 프롬프트·문장별 설계 이유·풀이·실패 대처는 [별도 강사용 문서](instructor-prompts.md)에 둔다. A를 보존하기 전에 기준본을 보여주지 않는다.

S01~S07은 독립 비교이므로 앞 상황의 실제 결과를 다음 비교 입력으로 쓰지 않는다. 마지막 연속 제작에서만 선택한 자기 프롬프트와 실제 결과를 이어 쓴다. 상황별 미션·예상 산출물·평가·비교 질문·막혔을 때의 조치는 [학생 실습](practice.md)을 기준으로 한다.

S02는 총괄 하나와 실제 하위 둘 이내다. 서로 독립된 자료 조사만 나누고 총괄이 대조·통합한다. 도구가 지원하지 않으면 새 대화 두 개를 수동 중계하고 실제 하위 에이전트 실행과 구분한다. 나머지 단계는 단일 에이전트다. Skill·MCP·Plugin의 개념은 강의에서 배우되 설치를 실습 완료 조건으로 삼지 않는다. 반복 절차를 Skill 초안으로 옮기는 활동만 선택 확장으로 둔다.

## 평가

상황별 A/B를 요구 충족·근거 정확성·위임과 범위 통제·재작업과 설명의 네 축으로 평가한다. 각 0~2점, 총 8점이며 모든 기준은 사전 공개한다. 학생이 파일·호출 기록·원자료를 근거로 판정하게 한다. 기능 설치 수·역할 수·프롬프트 길이는 점수가 아니다.

비교는 같은 입력·모델·도구·초기 지침·시간 상한에서 진행한다. A/B 각각 최초 요청 1회와 보완 최대 1회, S02는 하위 둘 각 조사 1회, 기본 온라인 검색 0회다. 호출·수정·시간·표시된 사용량을 기록하며 미표시 값은 미확인으로 남긴다. 강사 기준본의 우승을 전제하지 않고, 짧은 관찰로 특정 문장의 효과나 성능 향상률을 일반화하지 않는다.

최종 완료에는 블로그 한 편·출처 대조·사람의 화면 확인·정직한 기록·자기 선택 설명이 필요하다. 결과 생성, 실제 하위 에이전트 수행, 검증 완료, 학생 이해는 각각 판정한다. 미지원·실패의 정확한 기록을 성공한 실행으로 바꾸지 않는다. 사용자의 취향은 존중하고 사실은 자료로 검증한다. 무조건 반대하는 답을 정답으로 삼지 않는다.

## PDF·제품 근거와 강사 준비

각 원고의 PDF 연결 상자는 물리적 페이지, 활용·교정·새 내용을 유지한다. 29쪽의 형식 지정은 few-shot과 구별하고, 영→불 BLEU 41.0 표기는 원논문 41.8과 대조한다. MECE는 실행 독립성을 보장하지 않으며 CoT 권고·연구 평가는 모델과 과제의 적용 범위를 밝힌다.

강사는 제공 자료 세 개, 파일 접근·실제 하위 에이전트 화면, 브라우저 열기, 공통 예산과 초기 지침을 사전 확인한다. [도구 안내](materials/blog/TOOLS.md)의 공식 근거·확인 날짜를 참고하되 학생 환경의 지원은 별도로 확인한다. 강의의 원논문·보고서 그림·계산 시연 준비와 블로그 실습 준비를 구분한다.

학생별 설정·계정·하위 에이전트 실제 수행·학습 효과는 수업에서 확인할 대상이다. 교재 문서와 예제 검증을 모든 학생 환경의 성공으로 확대하지 않는다.
